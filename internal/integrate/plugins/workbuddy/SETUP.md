# WorkBuddy 本机办公接入（导出说明）

本目录由讣告导出，供用户审阅。`SKILL.md` 在选择 Skill 导出时逐字节取自讣告现有技能文本。本目录没有插件 manifest，导出完成表示文件已经准备好；宿主导入与启用状态需要在 WorkBuddy 中确认。

## 发行版和执行位置

- `workbuddy` 对应 Windows 国内桌面版。官方 MCP 路径为用户 `%USERPROFILE%\.workbuddy\mcp.json` 与项目 `<项目>\.workbuddy\mcp.json`。
- 国际版单独核实。国际资料曾出现 `.workbuddy-ai` 模型配置目录；它的用户与项目 MCP 路径尚未验证。当前自动安装仅面向国内版，国际版可在其客户端配置界面核对实际文件及 stdio schema 后手动添加。
- MCP 服务运行在启动 `obit.exe` 的 Windows 电脑上，只处理用户确认属于该电脑的绝对路径。云模式、远程工作区及远端同名路径均不在本机接入范围，云任务应停用这个本机 MCP 服务。
- 当前没有 WorkBuddy 消费级 hook 接线，自动写后登记、会话差分和删除护栏均未启用。MCP 工具由模型主动调用；每次操作仍经过讣告现有安全检查。普通办公目录的自动寿命策略留待显式文件夹授权功能。

## 国内版 MCP

1. 选择用户级或项目级配置，运行讣告的 WorkBuddy MCP 安装计划并确认写入。
2. 在 WorkBuddy 侧边栏打开「插件 → MCP 服务器 → 配置 MCP」，核对 `mcpServers.obituary`。`command` 是已安装 `obit.exe` 的绝对路径，`args` 为 `["mcp"]`；其余服务器和用户字段保持原样。
3. 确认服务状态与工具列表。先在本机临时办公目录创建可丢弃样本，再明确请求模型用 `obit_bury` 下葬该绝对路径、用 `obit_graveyard` 查看记录、按返回编号用 `obit_resurrect` 恢复。另在临时 Git 项目中重复。此流程需要实际客户端验收，本导出未执行它。
4. 卸载 MCP 时仅移除已核对归属的 `obituary` 项；保留其他服务器。

## 手动导入已有技能

选择 Skill 导出后，本目录中的 `SKILL.md` 可供审阅。国内官方入口为「技能 → 添加技能 → 上传技能」，选择本地技能包，按客户端要求准备上传文件；随后在「已安装」确认内容与启用状态。本次没有验证上传包格式、插件 manifest 或 loader，自动导入与激活保持未配置状态。

导出文件的更新与卸载由逐文件归属回执保护；用户修改过的文件会保留。通过 WorkBuddy 上传的副本由宿主管理，卸载导出文件后仍需到「技能 → 已安装 → … → 卸载」处理副本。现有 `.codebuddy` 配置由独立接入负责，本安装计划保留它的全部内容。

协议来源和范围见同目录 `sources.json`。
