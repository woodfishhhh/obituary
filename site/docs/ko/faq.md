# 자주 묻는 질문

## 바로 삭제하지 않고 왜 매장하나요?

필요한지 확실하지 않은 파일을 영구 삭제하면 되돌릴 수 없습니다. Obituary는 먼저 묘지에 매장하고 기본 7일 동안 보관합니다. 그동안은 언제든 `obit resurrect`로 원래 위치에 되돌릴 수 있고, 보관 기간이 지난 뒤에만 영구 삭제합니다. 7일 안에 에이전트가 해당 파일을 찾으면 무덤 번호와 부활 명령을 즉시 알려 줍니다([묘지 알림](./grave-notices)).

## macOS와 Linux도 지원하나요?

네. 두 운영체제 모두 x64와 ARM64용 명령줄 도구와 백그라운드 프로그램을 제공하며 묘지, 부활, 자동 매장을 지원합니다. macOS는 launchd, Linux는 systemd 사용자 타이머로 만료 여부를 확인하고 에이전트 훅도 필요할 때 확인을 시작합니다. [빠른 시작](./index)을 참고하세요. Windows와 Linux에서는 `graveyard.mode = "recycle"`로 시스템 휴지통을 사용할 수 있습니다. `obit resurrect`가 아니라 휴지통에서 복원하세요. macOS에서는 묘지만 지원합니다.

## Windows에서 ‘Windows의 PC 보호’가 표시되면 어떻게 하나요?

Obituary에는 아직 코드 서명이 없습니다. 브라우저로 압축 파일을 다운로드한 경우 ‘추가 정보 → 실행’을 선택하세요. Scoop, winget, 설치 스크립트로 설치하면 보통 이 경고가 나타나지 않습니다. 세 방법 모두 먼저 압축 파일의 SHA-256을 확인합니다.

## ARM64에서도 작은 창을 사용할 수 있나요?

아니요. `obit-gui.exe`는 x64 전용입니다. ARM64 버전에는 명령줄과 트레이가 있습니다.

## 아직 커밋하지 않은 코드가 자동 등록될 수 있나요?

아니요. 자동 등록은 기본적으로 꺼져 있어서 에이전트가 `obit mark`로 등록한 항목과 사용자가 상황에 맞는 메뉴에서 추가한 항목만 들어갑니다. 켠 경우에도 Git 작업 트리 안에서 Git이 추적하지 않는 항목만 대상입니다. 아직 커밋하지 않은 코드처럼 어떤 규칙과도 일치하지 않는 새 파일은 목록에 올리지 않으며, 의존성, 빌드 결과물, 캐시도 건드리지 않습니다. 규칙이나 제안으로 등록한 항목이라도 만료 시점에 커밋되어 있으면 매장하지 않습니다. [등록 대상](./auto-register)을 참고하세요.

## Git이 응답하지 않거나 `.gitignore`의 범위가 매우 넓으면 어떻게 되나요?

Obituary는 등록하기 전에 Git이 추적하는 항목인지 확인합니다. Git이 설치되지 않았거나 시간 초과 또는 저장소 손상으로 답을 얻지 못하면 아무것도 등록하지 않습니다. Git 저장소 밖의 폴더는 자동 등록하지 않으며 사용자나 에이전트가 `obit mark`로 수명을 직접 지정해야 합니다. `.gitignore`의 범위가 넓어도 미추적 항목만 늘어날 뿐입니다. 자동 등록은 여전히 기본 규칙이나 사용자가 신뢰한 `.obitrules`에 해당하는 항목만 처리합니다.

## 에이전트가 내 파일을 자기가 만든 것으로 처리해 제안을 건너뛸 수 있나요?

아니요. 기본값에서는 자동 등록이 꺼져 있어 동의 없이 자동 등록되지 않습니다. 단계별 모드를 켜도 해당 세션에서 에이전트가 만든 것이 확인된 파일만 바로 등록됩니다. 훅이 쓰기를 관찰했고, 세션 시작 시점의 스냅샷에 없었으며, 파일 시스템의 생성 시각도 세션 시작 이후여야 합니다. 이전부터 있던 파일이나 다른 프로그램이 만든 파일은 먼저 제안합니다. 에이전트가 유도에 따라 오래된 폴더를 규칙에 맞는 이름으로 바꾸더라도 생성 시각은 그대로이므로 제안만 생성됩니다. Git이 추적하는 파일은 어떤 모드에서도 자동 등록하지 않습니다. 바로 등록한 항목은 나중에 알리며 `obit spare`로 취소할 수 있습니다. 매장한 뒤에도 7일 동안은 부활시킬 수 있습니다.

## 에이전트가 나 대신 제안을 승인할 수 있나요?

아니요. 제안 승인·거부, `.obitrules` 신뢰, 묘지 항목 영구 삭제, 설정 변경(제안 모드 포함)을 위한 MCP 도구는 없습니다. 에이전트는 제안을 전달할 수만 있습니다.

## 휴지통 모드에서도 `obit resurrect`을 사용할 수 있나요?

아니요. `config.toml`에 `mode = "recycle"`을 설정하면 매장한 항목은 시스템 휴지통으로 이동합니다. 휴지통에서 직접 복원하세요.

## 잠시 동안 어떻게 해제하나요?

- 훅: `OBIT_DISABLED=1`
- 삭제 가드: `OBIT_GUARD_RM=0`
- 자동 정리: 트레이 메뉴에서 "일시 중지"

## 데이터는 어디에 있습니까?

`%LOCALAPPDATA%\obituary`에 장부, 감사 로그, 데몬 로그, 이 드라이브의 묘지가 있습니다. 설정 파일은 `%APPDATA%\obituary\config.toml`입니다. [작동 방식](./how-it-works#where-the-data-lives)을 참고하세요.

## 제거하면 묘지가 지워집니까?

아니요. `obit uninstall`은 기본적으로 묘지와 장부를 남깁니다. 둘 다 지우려는 경우에만 `--purge-data`를 추가하세요. [제거](./uninstall)를 참고하세요.
