# 창, 트레이 및 컨텍스트 메뉴

명령줄 없이 파일을 부활시키고 제안을 승인하거나 설정을 바꿀 수 있습니다.

## 세 플랫폼에서 되는 것

작은 창, 트레이, 데스크톱 알림은 Windows, macOS, Ubuntu 24.04 모두에 있습니다. macOS와 Ubuntu의 데스크톱 버전은 아직 미리 보기입니다. 다른 Linux 배포판에는 데스크톱 버전이 없으므로 명령줄을 쓰세요.

| | Windows | macOS | Ubuntu 24.04 |
| --- | --- | --- | --- |
| 작은 창 | `obit-gui.exe`, x64 전용 | `Obituary.app`, Intel과 Apple 실리콘 공용 | `.deb` 패키지, amd64 전용 |
| 트레이 | 작업 표시줄 알림 영역 | 메뉴 막대 | 트레이. 데스크톱이 StatusNotifierItem을 제공해야 함 |
| 로그인 시 트레이 시작 | `obit init`에서 기본으로 켜짐 | 설정에서 전환 | 설정에서 전환 |
| 만료 처리 | 상주하는 트레이 | LaunchAgent | systemd |
| 데스크톱 알림 | 있음 | 있음 | 있음 |
| 컨텍스트 메뉴 | 탐색기 | Finder: 빠른 동작 | Nautilus: 스크립트 · Dolphin |
| 날짜 태그 | 있음 | Finder | Dolphin |
| 휴지통 모드 | 있음 | 없음(묘지만) | 있음 |
| 설치 방법 | 설치 스크립트, Scoop, winget, 압축 파일 | DMG | `.deb` |
| 처음 열 때 | 직접 내려받은 압축 파일은 SmartScreen 경고가 나올 수 있음 | 수동 허용이 필요함. [아래](#서명되지-않은-app을-처음-열기) 참고 | 바로 열림 |
| 요구 사항 | WebView2 런타임 | 1.6.0은 macOS 26 필요(1.6.1에서 수정) | GTK 3, WebKitGTK 4.1(apt가 자동 설치) |

Windows에서는 로그인 시 시작하는 예약 작업, macOS에서는 사용자 LaunchAgent, Linux에서는 그래픽 세션의 사용자 systemd 서비스가 트레이를 감독합니다. 비정상 종료 후 60초 뒤에 재시작하며, 15분 안에 세 번째로 비정상 종료하면 재시도를 중단합니다.

데스크톱에서 감독 기능을 켜면 트레이 프로세스가 만료 시점에 처리하고 별도 작업이 한 시간마다 누락된 항목을 확인합니다. 이 데이터 디렉터리에 트레이 감독이 설정되지 않으면 5분마다 확인합니다.

Windows의 기존 예약 작업은 현재 설치용으로 생성한 정의와 일치할 때만 이전합니다. 원래 정의를 보관해 되돌릴 수 있으며, 수정하거나 비활성화한 작업은 그대로 둡니다.

## macOS 작은 창과 메뉴 막대 아이콘

릴리스 페이지에서 universal DMG(`obituary_<버전>_darwin_universal.dmg`)와 `checksums.txt`를 내려받고, SHA-256을 확인한 뒤 DMG를 엽니다. Obituary.app을 응용 프로그램 폴더로 드래그하고 DMG를 추출한 다음, 응용 프로그램 폴더에서 app을 여세요. 먼저 드래그해 두는 것은 로그인 시 시작 항목이 app의 위치를 기록하기 때문입니다. DMG 안에서 바로 실행하면 DMG를 추출하는 순간 그 위치가 사라집니다.

app에는 작은 창, 메뉴 막대 아이콘, 함께 쓰는 `obit`과 `obitd`가 들어 있습니다. 창이나 메뉴 막대 아이콘을 닫아도 영향을 받지 않습니다. 작은 창의 Settings에서 ‘Start the tray at sign-in’을 켜면 Obituary 전용 사용자 LaunchAgent가 설치되어 로그인할 때 메뉴 막대 아이콘이 나타납니다. 끄면 이 항목만 제거됩니다.

`obit daemon enable`로 독립적인 만료 확인 작업을 설치합니다. 창이나 메뉴 막대 아이콘을 닫아도 이 작업은 유지됩니다.

`Obituary.app`을 삭제해도 사용자 데이터는 기본 경로인 `~/Library/Application Support/obituary/`에 남습니다. `store.json`은 장부, `config.toml`은 설정 파일이며, 이 볼륨에서 매장한 파일은 `graveyard/`에 보관됩니다.

### 서명되지 않은 app을 처음 열기

이 릴리스에는 Developer ID 서명도 공증도 없어서 macOS가 처음에 한 번 막습니다. 신뢰할 수 있는 릴리스 페이지에서 내려받았는지, SHA-256이 맞는지 확인한 뒤 먼저 평소처럼 한 번 여세요. 개발자를 확인할 수 없다는 메시지가 나오면 ‘시스템 설정 → 개인정보 보호 및 보안’에서 페이지 아래쪽의 Obituary를 찾아 ‘그래도 열기’를 누르고, 한 번 더 확인한 뒤 다시 엽니다. 이를 위해 Gatekeeper를 전체적으로 끄거나 격리 속성을 재귀적으로 지우지 마세요. app이 손상되었다거나 악성 코드를 포함한다고 나오거나, 회사 정책이 열기를 막는다면 거기서 멈추세요.

### 1.6.0은 macOS 26이 필요함

1.6.0의 macOS 작은 창에는 macOS 26이 필요합니다. macOS 15 이하에서는 이 app이 현재 버전과 호환되지 않는다고 나오며 열리지 않습니다. 이 문제는 1.6.1에서 수정됩니다.

## Ubuntu 24.04(amd64)

릴리스 페이지에서 데스크톱 패키지 `obituary_<버전>_linux_amd64.deb`와 `checksums.txt`를 내려받습니다. 내려받은 디렉터리에서 아래 명령을 실행하세요. `VERSION`은 실제 버전 번호로 바꾸며, 확인에 성공한 경우에만 설치됩니다.

```bash
file=obituary_VERSION_linux_amd64.deb
grep -F "  $file" checksums.txt | sha256sum --check --strict - && sudo apt install "./$file"
```

설치한 뒤에는 앱 목록에서 Obituary를 엽니다. 작은 창은 GTK 3와 WebKitGTK 4.1을 쓰며, 둘 다 apt가 패키지와 함께 설치합니다. 프로그램은 `/usr/libexec/obituary/`에 놓이고 PATH에는 들어가지 않습니다. 터미널에서 `obit`을 쓰려면 설치 스크립트로 명령줄을 따로 설치하세요.

트레이는 데스크톱이 StatusNotifierItem을 제공해야 하는데, GNOME은 기본으로 제공하지 않습니다. 그럴 때도 확장 기능 없이 앱 목록에서 같은 창을 열 수 있지만, 트레이 아이콘은 없습니다. 다음 로그인 때 트레이가 자동으로 나타나게 하려면 Settings에서 ‘Start the tray at sign-in’을 켜세요. 끄면 Obituary가 쓴 자동 시작 항목이 삭제됩니다. 제거는 [제거](./uninstall)를 참고하세요.

## 트레이

`obit init`을 실행하면 로그인할 때 트레이 아이콘이 나타납니다. 메뉴에는 다음 항목이 있습니다.

- 최근 매장한 항목: 클릭하면 부활합니다.
- 앞으로 24시간 안에 만료되는 항목
- 자동 정리 일시 중지 또는 재개
- Open Obituary: 작은 창을 엽니다. `obit-gui.exe`가 `obitd.exe`와 같은 폴더에 없으면 그 이유를 알림으로 보여 줍니다.
- 종료: 트레이는 종료하지만 예약된 작업은 계속 실행됩니다.

## 작은 창

`obit-gui.exe`에는 Expiring, Graveyard, For you, Settings, Logs의 다섯 페이지가 있습니다. 시작 메뉴의 ‘Obituary’, 바탕 화면 바로 가기, 트레이 메뉴의 ‘Open Obituary’ 중 어느 것으로든 열 수 있습니다.

- 홈 화면 위쪽에 ‘Auto registration: off’ 또는 ‘on’이 표시되며 클릭하면 설정이 열립니다. For you 상단이나 Settings에서 끄기(기본값으로 사용자와 에이전트가 등록한 항목만 포함), 단계별, 완전 자동, 매번 확인 중 하나를 선택합니다. [등록 대상](./auto-register)을 참고하세요. 승인 없이 등록된 항목은 아래의 ‘Handled automatically’에 표시됩니다. 항목마다 한 번의 클릭으로 등록을 취소해 카운트다운을 멈추고 제자리에 두거나 수명을 연장할 수 있습니다.
- 만료 후에도 다른 프로그램이 파일을 열고 있는 등의 이유로 매장하지 못한 항목은 For you의 ‘Burials that failed’에 사유 및 다음 재시도 시각과 함께 표시됩니다. 재시도 간격은 점차 길어지며 실패가 반복되면 멈추고 사용자의 결정을 기다립니다. ‘Retry’는 즉시 다시 시도하고 ‘Stop tracking’은 추적을 끝내고 항목을 제자리에 둡니다.
- Settings에서 묘지 용량 한도(프리셋 또는 직접 입력)를 설정할 수 있으며, 한도를 낮출 때는 삭제될 묘지를 미리 보여 주고 확인을 받습니다. 한도가 켜져 있으면 Graveyard 상단에 사용량 막대가 표시되고, 단일 항목이 한도를 초과하면 제자리에 둔 채 For you에 표시됩니다.
- Docker가 실행 중이 아니면 컨테이너 제안의 승인 버튼은 비활성화되며 카드에 사유가 표시됩니다. Docker를 시작한 뒤 승인하세요.
- `.obitrules` 파일을 신뢰하면 창에 나타난 정확한 버전만이 신뢰됩니다.
- 창, 트레이, 상황에 맞는 메뉴의 언어는 `config.toml`의 `[ui] language` 설정을 따릅니다. `auto`, `zh-CN`, `en` 중에서 선택할 수 있고 `auto`는 Windows 언어를 따릅니다. Settings에서도 바꿀 수 있습니다.
- 작은 창은 x64 전용이며 WebView2 런타임이 필요합니다. Windows 11에 내장되어 있고 대부분의 Windows 10 기기에도 설치되어 있습니다.

### 업데이트

‘Settings → About and updates’에서 새 안정 버전을 설치할 수 있습니다. Obituary는 창과 실행 중인 트레이를 닫고 처음 설치한 경로(Scoop, WinGet 또는 스크립트)로 업데이트한 뒤 트레이와 창을 다시 열려고 시도합니다. 실패하면 같은 페이지에 오류와 로그 경로가 표시됩니다.

직접 압축을 푼 복사본도 그 자리에서 업데이트할 수 있으며, 버튼에는 ‘Download and restart to update’라고 표시됩니다. Obituary는 GitHub에서 릴리스를 내려받고(GitHub가 10초 안에 응답하지 않으면 중국 본토 미러 사용) SHA-256을 확인한 뒤에야 창을 닫고, 그 폴더에 있는 Obituary 자신의 프로그램(`obit`, `obitd`, `obit-gui`)만 교체합니다. 폴더의 다른 파일은 그대로 두며 PATH와 시작 메뉴도 건드리지 않습니다. 이전 프로그램은 같은 위치의 숨김 폴더 `.obituary-update-…`에 하루 동안 보관된 뒤 묘지로 옮겨지며 부활시킬 수 있습니다. 새 `obit`가 실행되지 않는 경우를 포함해 어느 단계에서든 실패하면 이전 버전으로 되돌립니다. 조건은 안정 버전일 것(개발 빌드 아님), 릴리스의 모든 프로그램이 일반 파일로 폴더에 있을 것, 현재 사용자가 관리자 권한 없이 폴더에 쓸 수 있을 것입니다. 하나라도 맞지 않으면 화면에 어느 조건인지 표시되며, 릴리스 페이지에서 새 버전을 내려받아 교체할 수 있습니다. 터미널에서는 `obit update --apply`로 같은 일을 합니다. ‘What changed’의 릴리스 노트는 창의 언어로 표시되며, 해당 언어가 없으면 영어로 표시됩니다.

### 여덟 가지 테마

‘Settings → Appearance’에서 바꾸면 이 컴퓨터의 창 모양에만 즉시 적용됩니다.

| 테마 | 설명 |
|---|---|
| 달력 | 하루에 한 열씩, 파일이 매장되거나 영구 삭제되는 날짜에 표시됩니다. 더 늦은 날짜로 끌어 수명을 연장하거나 날짜 머리글을 클릭해 해당 날짜 항목을 모두 선택하고 하단 캡슐 바에서 일괄 연장·매장·부활·영구 삭제(매장과 영구 삭제는 별도 확인)를 실행할 수 있습니다. |
| 한 줄 | 키보드로 파일을 찾고 Enter를 눌러 부활시키거나 수명을 연장합니다. 입력란은 한 줄입니다. |
| 터널 | 시간을 3D 터널로 표시합니다. 가까울수록 만료 시점이 빠릅니다. 스크롤로 시간을 이동합니다. |
| Vigil | 어두운 화면에 파일마다 등이 하나씩 켜집니다. 어두운 등일수록 만료가 가깝습니다. |
| Notices | 신문의 부고란처럼 세리프 글꼴과 단을 사용합니다. 부활시키면 도장이 찍힙니다. |
| 지평선 | 지면 위에는 추적 중인 파일, 아래에는 묘지를 표시합니다. |
| Mica | 사이드바를 갖춘 Windows 11 기본 디자인입니다. |
| Night | 상단 바가 있는 차분한 어두운 테마입니다. |

## 상황에 맞는 메뉴

`obit init`은 기본적으로 현재 사용자에게만 파일 탐색기의 상황에 맞는 메뉴를 설치합니다. 파일이나 폴더를 오른쪽 클릭해 ‘Add to Obituary’를 선택하면 두 가지 방식이 있습니다.

- **1일 / 7일 / 30일**: 기한이 되면 매장합니다. 그전에는 평소처럼 사용하면 됩니다.
- **Bury now (recoverable)**: 즉시 묘지로 옮깁니다. 보관 기간(기본 7일) 동안 부활시킬 수 있습니다.

파일을 여러 개 선택해 한꺼번에 추가할 수 있습니다. 알림에 등록된 개수, 매장 예정 시점, 실패한 개수가 표시됩니다. Windows 11의 새 메뉴에는 보이지 않으므로 ‘더 많은 옵션 표시’를 선택하거나 Shift를 누른 채 오른쪽 클릭하세요. `obit init --dry-run`은 각 메뉴 항목과 명령을 나열하고 `obit doctor`는 설치 상태를 점검합니다.

업그레이드 후 탐색기 메뉴 전체가 다른 지원 언어로 표시되더라도 메뉴는 정상 작동합니다. `obit doctor`는 정보로만 알립니다(JSON에서는 `installation: label-language-mismatch`). `obit init --context-menu --yes`를 실행하면 현재 인터페이스 언어로 바뀝니다.

Finder에서는 빠른 동작, Nautilus에서는 스크립트 → Obituary를 사용하세요. Dolphin의 서비스 메뉴는 빈 공간과 선택한 폴더 하나를 구분할 수 없어 두 경우 모두 작업을 표시하지 않습니다. Dolphin에서는 파일 하나 또는 여러 항목을 선택하면 Obituary 메뉴가 나타나고, 폴더 정책은 폴더를 두 개 이상 선택해야 합니다. 폴더 하나만 선택했을 때는 CLI나 Nautilus를 사용하세요. 기존 메뉴는 `obit init --context-menu --yes` 명령으로 갱신하세요.

## 아이콘과 메뉴

`obit init`은 기본적으로 아래 항목을 설정합니다. 각 항목은 ‘Settings → Icons and menus’에서 따로 켜고 끌 수 있습니다.

| 설정 | 적용 대상 |
|---|---|
| 트레이 아이콘 | 알림 영역의 Obituary 아이콘입니다. 숨겨도 정리는 계속됩니다. |
| 작업 표시줄 아이콘 | 창이 열린 동안 작업 표시줄에 아이콘을 표시할지 결정합니다. |
| 시작 메뉴 | 시작 메뉴의 ‘Obituary’ 항목입니다. |
| 바탕 화면 바로 가기 | 바탕 화면의 ‘Obituary’ 바로 가기입니다. |
| 상황에 맞는 메뉴 | 파일 탐색기의 ‘Add to Obituary’ 메뉴입니다. |

설치할 때 원하지 않으면 `obit init --no-context-menu`로 컨텍스트 메뉴를, `--no-shortcuts`로 시작 메뉴와 바탕 화면 바로 가기를 만들지 않습니다. 두 옵션은 제거할 때도 같은 방식으로 작동합니다. `obit init --uninstall --no-shortcuts`는 기존 바로 가기를 남기고 나머지를 평소대로 걷어 내며, `--no-context-menu`는 컨텍스트 메뉴에 대해 똑같이 동작합니다.

탐색기에 표시되는 매장 날짜는 [폴더 정책](./folder-policies#dates-in-explorer)을 참고하세요.
