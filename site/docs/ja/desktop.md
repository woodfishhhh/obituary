# ウィンドウ、トレイ、右クリックメニュー

コマンドラインを使わずに、ファイルの復活、提案の承認、設定の変更ができます。

## 3 つのプラットフォームでできること

小窓、トレイ、デスクトップ通知は Windows、macOS、Ubuntu 24.04 のすべてにあります。macOS と Ubuntu のデスクトップ版は、今のところプレビュー版です。ほかの Linux ディストリビューションにはデスクトップ版がないので、コマンドラインを使ってください。

| | Windows | macOS | Ubuntu 24.04 |
| --- | --- | --- | --- |
| 小窓 | `obit-gui.exe`（x64 のみ） | `Obituary.app`（Intel と Apple シリコン共通） | `.deb` パッケージ（amd64 のみ） |
| トレイ | タスクバーの通知領域 | メニューバー | トレイ。デスクトップが StatusNotifierItem を提供している必要あり |
| ログイン時にトレイを起動 | `obit init` で既定でオン | 設定で切り替え | 設定で切り替え |
| 期限の処理 | 常駐するトレイ | LaunchAgent | systemd |
| デスクトップ通知 | あり | あり | あり |
| コンテキストメニュー | エクスプローラー | Finder: クイックアクション | Nautilus: スクリプト · Dolphin |
| 日付タグ | あり | Finder | Dolphin |
| ごみ箱モード | あり | なし（墓地のみ） | あり |
| インストール方法 | インストールスクリプト、Scoop、winget、アーカイブ | DMG | `.deb` |
| 初回の起動 | 手動でダウンロードしたアーカイブでは SmartScreen の警告が出ることがある | 手動で許可が必要。[下記](#未署名-app-を初めて開くとき)を参照 | そのまま開ける |
| 必要なもの | WebView2 ランタイム | 1.6.0 は macOS 26 が必要（1.6.1 で修正） | GTK 3 と WebKitGTK 4.1（apt が自動でインストール） |

Windows はログオン時のスケジュールタスク、macOS はユーザーの LaunchAgent、Linux はグラフィカルセッションの systemd ユーザーサービスでトレイを監視します。異常終了後は60秒待って再起動し、15分以内に3回異常終了すると再試行を止めます。

デスクトップ版で監視が有効な場合、トレイの常駐プロセスが期限に合わせて処理し、独立したジョブが1時間ごとに取りこぼしを確認します。そのデータディレクトリでトレイの監視が無効なら、ジョブは5分ごとに実行されます。

Windows の旧タスクは、現在のインストール用に作られた定義と一致する場合のみ移行します。元の定義を保存して復元できるようにし、変更済み・無効化済みのタスクはそのまま残します。

## macOS の小窓とメニューバーアイコン

リリースページから universal DMG（`obituary_<バージョン>_darwin_universal.dmg`）と `checksums.txt` をダウンロードし、SHA-256 を確認してから DMG を開きます。Obituary.app を「アプリケーション」にドラッグし、DMG を取り出してから、「アプリケーション」の中の app を開いてください。先にドラッグしておくのは、ログイン時の起動エントリが app の場所を記録するためです。DMG の中から直接実行していると、DMG を取り出した時点でその場所がなくなります。

app には、小窓、メニューバーアイコン、組み合わせて使う `obit` と `obitd` が入っています。インストールは `obit daemon enable` で行い、ウィンドウやメニューバーアイコンを閉じても影響を受けません。小窓の Settings で「Start the tray at sign-in」をオンにすると、Obituary 専用のユーザー LaunchAgent が入り、ログインするとメニューバーアイコンが現れます。オフにすると、この項目だけが削除されます。

独立した期限チェックは `obit daemon enable` でインストールできます。ウィンドウやメニューバーのアイコンを閉じても動作します。

`Obituary.app` を削除しても、デフォルトでは `~/Library/Application Support/obituary/` にデータが残ります。`store.json` は台帳、`config.toml` は設定ファイルで、このボリュームで埋葬したファイルは `graveyard/` に残ります。

### 未署名 app を初めて開くとき

このリリースには Developer ID の署名も公証もないため、macOS は最初に一度止めます。信頼できるリリースページからダウンロードしたことと SHA-256 を確認したうえで、まず普通に一度開いてください。開発元を検証できないと表示されたら、「システム設定 → プライバシーとセキュリティ」を開き、ページの下の方にある Obituary で「このまま開く」を選び、もう一度確認してから、開き直します。そのために Gatekeeper を全体で無効にしたり、隔離属性を再帰的に消したりしないでください。app が破損している、マルウェアを含む、あるいは会社のポリシーで開けないと表示された場合は、そこで中止してください。

### 1.6.0 は macOS 26 が必要

1.6.0 の macOS の小窓には macOS 26 が必要です。macOS 15 以前では、この app は現在のバージョンと互換性がないと表示され、開けません。この問題は 1.6.1 で修正されます。

## Ubuntu 24.04（amd64）

リリースページからデスクトップパッケージ `obituary_<バージョン>_linux_amd64.deb` と `checksums.txt` をダウンロードします。ダウンロードしたディレクトリで次のコマンドを実行します。`VERSION` は実際のバージョン番号に置き換えてください。確認に成功した場合にだけインストールされます。

```bash
file=obituary_VERSION_linux_amd64.deb
grep -F "  $file" checksums.txt | sha256sum --check --strict - && sudo apt install "./$file"
```

インストール後は、アプリケーション一覧から Obituary を開きます。小窓は GTK 3 と WebKitGTK 4.1 を使い、どちらも apt がパッケージと一緒にインストールします。プログラムは `/usr/libexec/obituary/` に置かれ、PATH には入りません。ターミナルで `obit` を使いたい場合は、インストールスクリプトでコマンドラインを別に入れてください。

トレイにはデスクトップ側が StatusNotifierItem を提供している必要があり、GNOME は既定では提供していません。その場合も、拡張機能を入れずにアプリケーション一覧から同じウィンドウを開けますが、トレイアイコンは出ません。次回のログイン時にトレイを自動で出したいときは、Settings で「Start the tray at sign-in」をオンにします。オフにすると、Obituary が書いた自動起動のエントリが削除されます。アンインストールは[アンインストール](./uninstall)を参照してください。

## トレイ

`obit init` を実行すると、ログイン時にトレイアイコンが表示されます。メニューから次の操作ができます。

- 最近埋葬した項目を表示し、クリックして復活する。
- 24 時間以内に期限が切れる項目を確認する。
- 自動クリーンアップを一時停止・再開する。
- 「Open Obituary」で小ウィンドウを開く。`obit-gui.exe` が `obitd.exe` と同じディレクトリにないときは、通知で理由を知らせます。
- トレイを終了する。スケジュールされたタスクは引き続き動作します。

## 小窓

`obit-gui.exe` には Expiring、Graveyard、For you、Settings、Logs の 5 ページがあります。スタートメニューの「Obituary」、デスクトップのショートカット、トレイの「Open Obituary」から開けます。

- ホーム上部の「Auto registration: off」または「on」をクリックすると設定が開きます。For you の上部または Settings で、無効（既定。ユーザーとエージェントが登録したものだけ）、段階的、全自動、すべて確認の 4 モードを切り替えられます。[登録の対象](./auto-register)を参照してください。確認なしで登録された項目は下の「Handled automatically」に並びます。各項目はワンクリックで登録を取り消して元の場所に残すか、寿命を延長できます。取り消すとカウントダウンは止まります。
- 期限が切れても埋葬できなかった項目（他のプログラムが開いているファイルなど）は、For you の「Burials that failed」に理由と次回の試行時刻が表示されます。再試行の間隔は徐々に長くなり、失敗が続くとユーザーの判断を待ちます。「Retry」は今すぐ再試行、「Stop tracking」は追跡をやめて項目を元の場所に残します。
- Settings で墓地の容量上限（プリセットまたは任意サイズ）を設定できます。上限を下げる前は削除される墓地をプレビューして確認します。上限設定時は Graveyard に使用量バーが表示され、単体で上限を超える項目は元の場所に残って For you に表示され、永久削除、延長、追跡をやめる、または上限の引き上げを選べます。
- Docker の停止中はコンテナの提案を承認できず、カードに理由が表示されます。Docker を起動してから承認してください。
- `.obitrules` を信頼した場合、その時点でウィンドウに表示されている版だけが対象です。
- ウィンドウ、トレイ、コンテキストメニューの言語は `config.toml` の `[ui] language` で設定します（`auto`、`zh-CN`、`en`。`auto` は Windows に従います）。設定画面でも切り替えられます。
- 小ウィンドウは x64 専用で、WebView2 ランタイムが必要です。Windows 11 には標準搭載され、ほとんどの Windows 10 端末にも入っています。

### 更新

「Settings → About and updates」から新しい安定版をインストールできます。Obituary はウィンドウとトレイを閉じ、元のインストール方法（Scoop、WinGet、スクリプト）で更新し、トレイとウィンドウの再起動を試みます。失敗した場合は同じページにエラーとログのパスが表示されます。

自分で展開したコピーもその場で更新できます。ボタンには「Download and restart to update」と表示されます。Obituary は GitHub からリリースをダウンロードし（GitHub が 10 秒以内に応答しない場合は中国本土のミラーを使用）、SHA-256 を検証してから、ウィンドウを閉じてそのフォルダー内の Obituary 自身のプログラム（`obit`、`obitd`、`obit-gui`）だけを置き換えます。フォルダー内の他のファイルには触れず、PATH やスタートメニューも変更しません。以前のプログラムは同じ場所の隠しフォルダー `.obituary-update-…` に 1 日残り、その後は墓地に移され、復活もできます。新しい `obit` が起動しない場合を含め、どの手順で失敗しても以前のバージョンに戻します。条件は、安定版であること（開発ビルドではない）、リリースのプログラムがすべて通常のファイルとしてフォルダーにあること、管理者権限なしで現在のユーザーがフォルダーに書き込めることです。満たさない条件があれば画面に示されるので、リリースページから新しい版をダウンロードして置き換えてください。ターミナルでは `obit update --apply` で同じことができます。「What changed」はウィンドウの言語で表示され、対応する言語がなければ英語になります。

### 8 種類の外観

「Settings → Appearance」で切り替えると、このコンピューターのウィンドウだけにすぐ反映されます。

| 外観 | 特徴 |
|---|---|
| カレンダー | 1 列が 1 日で、ファイルが埋葬または永久削除の日に並びます。後の日へドラッグすると寿命を延長でき、列ヘッダーをクリックするとその日の項目をまとめて選択し、下部のバーから一括延長・埋葬・復活・永久削除（埋葬と永久削除は別確認）ができます。 |
| 1 行 | キーボードだけで操作できる入力欄です。ファイルを探し、Enter で復活または延長します。 |
| トンネル | 時間を 3D のトンネルで表します。手前ほど期限が近く、スクロールで時間を移動できます。 |
| Vigil | 暗い画面で各ファイルを灯りで表します。暗い灯りほど期限が近いことを示します。 |
| Notices | セリフ体の段組みを使った新聞の訃報欄。復活するとスタンプが押されます。 |
| 地平線 | 追跡中のファイルは地上に、墓地は地下に表示されます。 |
| Mica | サイドバー付きの Windows 11 標準風の外観です。 |
| ナイト | 上部バーを備えた静かな暗いテーマ。 |

## コンテキストメニュー

`obit init` は既定で、現在のユーザーにだけエクスプローラーのコンテキストメニューを追加します。ファイルやフォルダーを右クリックし、「Add to Obituary」から選んでください。

- **1 日／7 日／30 日**：指定した期間が過ぎたら埋葬します。それまでは普通に使えます。
- **Bury now (recoverable)**：すぐに墓地へ移し、保持期間（既定は 7 日）中は復活できます。

複数のファイルを選んで一度に追加できます。通知には登録件数、埋葬予定、失敗件数が表示されます。Windows 11 の新しいメニューには表示されないため、「その他のオプションを確認」を選ぶか、Shift を押しながら右クリックします。`obit init --dry-run` は各項目とコマンドを一覧表示し、`obit doctor` は正しくインストールされているか確認します。

更新後にエクスプローラーの右クリックメニュー全体が別の対応言語になっていても、メニューはそのまま使えます。`obit doctor` は情報として表示します（JSON では `installation: label-language-mismatch`）。`obit init --context-menu --yes` で現在の表示言語に合わせられます。

Finder では「クイックアクション」、Nautilus では「スクリプト → Obituary」を使います。Dolphin のサービスメニューは余白と単一フォルダーの選択を区別できないため、どちらにも操作を表示しません。Dolphin では、ファイルを一つ、または複数の項目を選ぶと操作でき、ポリシーの設定にはフォルダーを二つ以上選ぶ必要があります。フォルダーを一つだけ選んだ場合は、CLI か Nautilus を使います。既存のメニューは `obit init --context-menu --yes` で更新してください。

## アイコンとメニュー

`obit init` で次の項目が既定で設定されます。それぞれ「Settings → Icons and menus」で切り替えられます。

| スイッチ | 内容 |
|---|---|
| トレイアイコン | 通知領域の Obituary アイコン。非表示にしてもクリーンアップは続きます。 |
| タスクバーアイコン | ウィンドウを開いている間、タスクバーに表示するかどうか。 |
| スタートメニュー | スタートの「Obituary」 |
| デスクトップショートカット | デスクトップに Obituary を表示 |
| コンテキストメニュー | エクスプローラーの「Add to Obituary」メニュー。 |

インストール時に不要なら、`obit init --no-context-menu` でコンテキストメニューを、`--no-shortcuts` でスタートメニューとデスクトップのショートカットを作成しません。この 2 つはアンインストール時にも使えます。`obit init --uninstall --no-shortcuts` は既存のショートカットを残してそれ以外を通常どおり取り除き、`--no-context-menu` はコンテキストメニューについて同じ動作をします。

エクスプローラーに表示する埋葬日については、[フォルダーポリシー](./folder-policies#dates-in-explorer)を参照してください。
