# よくある質問

## そのまま削除せず、なぜ埋葬するのですか？

まだ必要かもしれないファイルは、削除してしまうと戻せません。Obituary はまず墓地へ埋葬し、既定で 7 日間保管します。その間はいつでも `obit resurrect` で元の場所に戻せます。永久削除するのは保持期間が過ぎてからです。7 日以内にエージェントがそのファイルを使おうとすると、墓の番号と復活コマンドがその場で通知されます（[墓地からの通知](./grave-notices)）。

## macOS や Linux でも使えますか？

はい。どちらも x64 と ARM64 向けに CLI とバックグラウンドプログラムがあり、墓地、復活、自動埋葬に対応します。期限の確認には macOS で launchd、Linux で systemd のユーザータイマーを使います。必要に応じてエージェントのフックも確認を開始します。[クイックスタート](./index)を参照してください。 Windows と Linux では `graveyard.mode = "recycle"` でシステムのごみ箱を使えます。復元には `obit resurrect` ではなく、ごみ箱の復元機能を使います。macOS では墓地のみ対応しています。

## Windows に「Windows によって PC が保護されました」と表示されたら？

Obituary のコードにはまだ署名がありません。ブラウザーでアーカイブをダウンロードしてこの画面が出たら、「詳細情報」→「実行」を選びます。Scoop、winget、インストールスクリプトでは通常この画面は表示されません。いずれも先にアーカイブの SHA-256 を検証します。

## ARM64 版にも小ウィンドウはありますか？

ありません。`obit-gui.exe` は x64 専用です。ARM64 版ではコマンドラインとトレイを利用できます。

## コミット前のコードが自動登録されることはありますか？

ありません。自動登録は既定で無効です。対象はエージェントが `obit mark` で登録したものと、ユーザーがコンテキストメニューで追加したものだけです。有効にしても Git の作業ツリー内の未追跡項目に限られます。どのルールにも該当しない新規ファイル（コミット前のコードなど）は一覧に載らず、依存ファイル、ビルド出力、キャッシュも対象外です。ルールや提案に基づいて登録したものが期限までにコミットされた場合は埋葬しません。[登録の対象](./auto-register)を参照してください。

## Git が応答しない場合や `.gitignore` の範囲が広い場合は？

登録前に Git に追跡状況を問い合わせます。Git が未インストール、タイムアウト、リポジトリの破損などで答えられなければ、何も登録しません。Git リポジトリの外のフォルダーは自動登録されません。ユーザーかエージェントが `obit mark` で寿命を設定した場合だけが対象です。`.gitignore` の範囲が広くても未追跡の項目が増えるだけで、自動登録は組み込みルールか、ユーザーが信頼した `.obitrules` に一致するものに限られます。

## 自分のファイルをエージェントの成果物として、提案なしに登録できますか？

できません。自動登録は既定で無効で、承認なしに自動登録されるものはありません。段階モードで承認を省けるのは、そのセッション中にエージェントが作成したと確認できるファイルだけです。フックが書き込みを検知し、開始時のスナップショットに存在せず、ファイルシステム上の作成時刻も開始後でなければなりません。以前からあるファイルや他のプログラムが作成したファイルは提案にとどまります。エージェントが誘導されて古いフォルダーの名前をルールに合うものに変えても、作成時刻は変わらず、やはり提案が必要です。どのモードでも Git の追跡対象は自動登録しません。直接登録したものは後から通知し、`obit spare` で取り消せます。埋葬後も 7 日間は復活できます。

## エージェントが代わりに提案を承認できますか？

できません。提案の承認・却下、`.obitrules` の信頼、墓地の項目の永久削除、設定の変更（提案モードを含む）のための MCP ツールはありません。エージェントは提案を取り次ぐだけです。

## ごみ箱モードでも `obit resurrect` を使えますか？

使えません。`config.toml` で `mode = "recycle"` を設定した場合、埋葬した項目はシステムのごみ箱に移ります。戻すときはごみ箱から復元してください。

## 一時的に無効にするには？

- フック：`OBIT_DISABLED=1`
- 削除ガード：`OBIT_GUARD_RM=0`
- 自動クリーンアップ: トレイメニューの "一時停止"

## データはどこにありますか？

`%LOCALAPPDATA%\obituary` に台帳、監査ログ、デーモンのログ、このドライブの墓地があります。設定ファイルは `%APPDATA%\obituary\config.toml` です。[仕組み](./how-it-works#where-the-data-lives)を参照してください。

## アンインストールすると墓地も削除されますか？

いいえ。`obit uninstall` は既定で墓地と台帳を残します。両方とも削除したい場合に限り `--purge-data` を付けてください。[アンインストール](./uninstall)を参照してください。
