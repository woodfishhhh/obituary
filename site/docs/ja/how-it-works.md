# Obituary の仕組み

## ファイルの寿命

1. **登録**：ファイルやフォルダーに寿命を設定します。エージェントは `obit add debug.log 2h`、ユーザーはエクスプローラーのコンテキストメニューにある「Add to Obituary」を使います。[登録の対象](./auto-register)を参照してください。
2. **期限切れ**：`obit list` で残り時間を確認できます。期限前なら `obit extend` で延長するか、`obit spare` で追跡を終了してファイルを残せます。
3. **埋葬**：期限が来ると墓地へ移り、既定で 7 日間保管されます。`obit graveyard` で確認できます。
4. **復活または永久削除**：保持期間中は `obit resurrect <id>` で元の場所に戻せます。既存のファイルは上書きしません。期間が過ぎた後に初めて永久削除（`obit purge`）されます。

まだ必要か判断できないものは、`obit bury` で先に埋葬できます。そのままの状態で 7 日間は復活できます。

## 墓地の場所

墓地はファイルと同じドライブにあります。データディレクトリのあるドライブではその配下の墓地を、それ以外のドライブではルートにある隠しディレクトリ `.obituary` を使います。埋葬は名前変更だけで済むため速く、移動が途中までしか終わらないこともありません。

保持期間は設定で変更できます。埋葬先をシステムのごみ箱にすることもできます。その場合はごみ箱から復元してください。`obit resurrect` は使えません。

```toml
[graveyard]
mode = "graveyard"      # or "recycle": straight to the system Recycle Bin
retention_days = 7      # days the graveyard keeps things
```

設定ファイルは `%APPDATA%\obituary\config.toml` です。`obit config` で現在の内容を表示し、`obit config --create` でコメント付きの既定ファイルを作成できます。

## 他のファイルを誤って削除しない仕組み

- **永久削除するのは墓地の項目を消去するときだけです。** 埋葬のたびに専用の墓フォルダーを作り、そのファイル ID を記録します。永久削除や復活の前に、フォルダー自体が当初のものか、中身がちょうど 1 件か、それが埋葬した対象かを確認します。台帳が破損したり墓地がリンクに置き換わったりしても、墓地の外を削除することはありません。
- **復活先は元の場所だけです。** 同じ名前が使用中なら `name (resurrected).ext` のように別名で隣に戻します。両方が残り、実際のパスは結果に表示されます。削除された親フォルダーは作り直します。親がジャンクションやシンボリックリンクに変わった、既存のジャンクションの参照先が変わった、ドライブ文字が別のボリュームを指すようになった場合は、復活せず墓をそのまま残します。
- **名前ではなくファイルを識別します。** 各記録はボリュームのシリアル番号と 128 ビットのファイル ID を持ちます。名前や場所が変わっても元のファイルを見つけ、古いパスに別のファイルがあっても触れません。削除直前にも同一性を確認します。ハードリンクが複数あるファイルは対象外です。
- **保護対象のパスがあります。** ドライブのルート、`C:\Windows`、Program Files、ProgramData、ユーザープロファイル、デスクトップ、ドキュメント、ダウンロードなどのフォルダー自体とその親は対象外です。リダイレクトされたものも含みます。中の項目には寿命を設定できます。
- **Git リポジトリを保護します。** 階層の深さに関係なく `.git` を含むフォルダーで `obit add` または `obit bury` を実行するには `--force` が必要です。期限切れ時にも再確認し、確認が終わらなければ埋葬しません。
- **確かめられなければ削除しません。** 記録を破棄するのはファイルの消失を確認できたときだけです。アクセス拒否やボリュームの取り外しなどは後で再試行します。間隔は 1 分から徐々に長くなり、最長 1 日です。12 回連続で失敗すると処理を止め、判断を待ちます。理由は `obit list` と Decisions の「Burials that failed」に表示します。`obit extend <id> 1m`（Retry）で再試行し、`obit spare <id>`（Stop tracking）ならその場に残します。大きなフォルダーは埋葬前に最大 30 秒間 Git リポジトリを探します。確認が終わらなければ後でやり直し、リポジトリがあれば埋葬しません。
- **操作を記録します。** 登録、延長、取り消し、削除をすべて監査ログ（`obit log`）に記録します。

## バックグラウンド処理

既定では `obitd.exe` はログイン時に起動してトレイに常駐し、秒単位で期限どおりに埋葬します。インターフェースはトレイアイコンだけです。予備として Windows のスケジュールされたタスクも 5 分ごととログイン時に `obitd --once` を実行します。トレイを閉じた場合や一度も起動していない場合でも、期限切れの項目は埋葬し、保持期間が過ぎた墓は永久削除します。セッションの開始時と終了時にもエージェントのフックが処理を一巡させます。今すぐ行うには `obit reap` を実行します。

```powershell
obit daemon enable              # tray at login plus the fallback scheduled task (--dry-run lists what would be installed)
obit daemon status              # current mode and the next expiry (--json)
obit daemon disable             # remove the scheduled task and login start, and stop the running daemon (--dry-run previews)
```

`list`、`graveyard`、`stats`、`log` などの照会は読み取り専用で、埋葬を実行することはありません。

## データの保存場所 {#where-the-data-lives}

`%LOCALAPPDATA%\obituary` に `store.json`（台帳）、`audit.jsonl`（監査ログ）、`obitd.log`（デーモンのログ）、`graveyard\`（このドライブの墓地）があります。

保存先は `OBIT_HOME`（データ）、`OBIT_CONFIG_DIR`（設定）、`OBIT_USER_HOME`（ユーザーのホーム）で変更できます。
