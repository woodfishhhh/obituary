# Уведомления о захоронении

Прежде чем удалить файл навсегда, его можно похоронить, но тогда важно знать, где его искать. Если инструмент агента обращается к похороненному пути, который ещё можно восстановить, или к элементу внутри похороненного каталога, Obituary сообщает:

- номер могилы;
- когда похоронили объект;
- сколько времени осталось, чтобы его воскресить;
- `obit resurrect <id>`.

## Только уведомление

- Вызов инструмента не блокируется и не изменяется.
- Каждая могила упоминается один раз в сессии.
- Claude Code и Codex получают уведомление до запуска инструмента. Для других агентов момент уведомления указан в выводе `obit init --show`.
- В остальное время Obituary не отвлекает агента. В начале работы достаточно знать, что Obituary доступна; предварительно читать список не нужно.

Если Obituary уже установлена, повторно выполните `obit init`, чтобы включить уведомления.

## Сводка сеанса (необязательно)

Для экономии токенов в начале сеанса агенту показывают только предложения, требующие вашего решения, и только что автоматически зарегистрированные объекты. Чтобы добавить сводку, включите «Session summary» в настройках небольшого окна программы или укажите:

```toml
[hooks]
session_summary = true
```

Тогда агент увидит также объекты проекта, срок жизни которых истекает в ближайшие 24 часа, и недавно похороненные объекты, которые ещё можно воскресить. Временные каталоги `obit mktemp` в сводку не входят.

## Как проверить самостоятельно

```powershell
obit graveyard           # what is in the graveyard and when it will be purged
obit graveyard --here    # this folder only
obit resurrect <id>      # put it back; if the name is taken, it comes back renamed, never overwriting
obit resurrect --last    # undo the last deletion: everything one obit bury / obit rm buried comes back
```
