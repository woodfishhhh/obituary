# Частые вопросы

## Почему не удалить файл сразу?

Если удалить файл окончательно, а потом выяснится, что он нужен, вернуть его не получится. Obituary сначала хоронит файл на кладбище и по умолчанию хранит его семь дней. В это время `obit resurrect` в любой момент вернёт файл на место. Безвозвратно он удаляется только после срока хранения. Если за эти семь дней агент обратится к файлу, Obituary сразу сообщит ему номер могилы и команду для воскрешения (см. [уведомления о захоронении](./grave-notices)).

## Есть ли версии для macOS и Linux?

Да. Для обеих систем доступны командная строка и фоновый процесс для x64 и ARM64, с кладбищем, воскрешением и автоматическим захоронением. Сроки в macOS проверяются с помощью launchd, в Linux — с помощью пользовательского таймера systemd. При необходимости проверку также запускают хуки агентов. См. [быстрый старт](./index). Системная корзина, небольшое окно, значок в области уведомлений и контекстное меню доступны в версии для Windows.

## Что делать с предупреждением «Система Windows защитила ваш компьютер»?

Исполняемые файлы Obituary пока не подписаны. Если при загрузке архива через браузер появилось такое предупреждение, выберите «Подробнее → Выполнить в любом случае». При установке через Scoop, winget или скрипт предупреждение обычно не возникает. Все три способа сначала проверяют SHA-256 архива.

## Доступно ли небольшое окно на ARM64?

Нет. `obit-gui.exe` доступен только для x64. Сборка ARM64 включает командную строку и значок в области уведомлений.

## Может ли программа зарегистрировать код, который я ещё не закоммитил?

Нет. По умолчанию автоматическая регистрация выключена. Попадают в реестр только объекты, которые агент зарегистрировал с помощью `obit mark` или вы добавили через контекстное меню. Даже при включённой регистрации рассматриваются только неотслеживаемые объекты внутри рабочего дерева Git. Новые файлы вне правил, например ещё не закоммиченный код, не попадают в список. Зависимости, результаты сборки и кеши не затрагиваются. Если объект зарегистрировали по правилу или предложению, но к моменту истечения срока он уже попал в коммит, его не похоронят. См. [что попадает в реестр](./auto-register).

## Что будет, если Git не отвечает или `.gitignore` охватывает слишком много файлов?

Перед регистрацией Obituary спрашивает Git, отслеживает ли он объект. Если Git не установлен, истекло время ожидания или репозиторий повреждён и получить ответ нельзя, ничего не регистрируется. Папки вне Git-репозитория никогда не регистрируются автоматически. Задать им срок жизни с помощью `obit mark` можете только вы или агент. Широкие правила `.gitignore` лишь увеличивают число неотслеживаемых объектов. При автоматической регистрации по-прежнему учитываются только встроенные правила и файл `.obitrules`, которому вы доверяете.

## Может ли агент выдать мои файлы за свои и обойти предложение?

Нет. По умолчанию автоматическая регистрация выключена: без вашего согласия автоматически ничего не регистрируется. В многоуровневом режиме без одобрения регистрируются лишь файлы, для которых установлено, что их создал агент в этом сеансе: хук видел запись, в снимке на начало сеанса файла нет, а время создания в файловой системе позже начала сеанса. Для существовавших ранее файлов и файлов других программ всё равно создаётся предложение. Даже если агента убедят переименовать старую папку так, чтобы она подходила под правило, время её создания не изменится и папка попадёт лишь в предложение. Отслеживаемые Git файлы не регистрируются автоматически ни в одном режиме. О каждой прямой регистрации вы узнаете после её выполнения; отменить её можно командой `obit spare`. Похороненные объекты можно воскресить в течение семи дней.

## Может ли агент одобрить предложение за меня?

Нет. Для одобрения или отклонения предложений, доверия к `.obitrules`, безвозвратного удаления объектов с кладбища и изменения настроек, в том числе режима предложений, инструментов MCP нет. Агент может только передать предложение вам.

## Работает ли `obit resurrect` в режиме системной корзины?

Нет. При настройке `mode = "recycle"` в `config.toml` объекты перемещаются в системную корзину. Восстанавливать их нужно оттуда.

## Как временно отключить отдельные функции?

- Хуки: `OBIT_DISABLED=1`
- Защита удаления: `OBIT_GUARD_RM=0`
- Автоматическая очистка: «Пауза» в меню значка в области уведомлений.

## Где данные?

В `%LOCALAPPDATA%\obituary` находятся реестр, журнал аудита, журнал фонового процесса и кладбище на этом диске. Настройки хранятся в `%APPDATA%\obituary\config.toml`. См. [как это работает](./how-it-works#where-the-data-lives).

## При удалении программы кладбище тоже удалится?

Нет. По умолчанию `obit uninstall` оставляет кладбище и реестр. Добавьте `--purge-data` только в том случае, если действительно хотите удалить и то и другое. См. [удаление программы](./uninstall).
