# Справочник конфигурации

Настройки Obituary хранятся в файле `config.toml` в каталоге конфигурации. Этот файл необязателен: если его нет или в нём записано всего несколько строк, всё остальное работает со значениями по умолчанию. Команда `obit config` покажет, где лежит файл, создан ли он и какое значение сейчас фактически действует у каждой настройки. Команда `obit config --create` записывает файл с комментариями и всеми значениями по умолчанию — с него проще всего начать правку.

Каталог конфигурации — `%APPDATA%\obituary` в Windows, `~/Library/Application Support/obituary` в macOS и `~/.config/obituary` в Linux (или `obituary` внутри `XDG_CONFIG_HOME`, если она задана). Чтобы перенести его в другое место, задайте переменную окружения `OBIT_CONFIG_DIR`.

| Ключ | Значение по умолчанию | Допустимые значения |
| --- | --- | --- |
| `graveyard.mode` | `graveyard` | `graveyard`, `recycle` |
| `graveyard.retention_days` | `7` | целое число от 1 до 3650 |
| `proposals.mode` | `off` | `off`, `tiered`, `auto`, `ask` |
| `hooks.session_cleanup` | `true` | `true`, `false` |
| `hooks.session_summary` | `false` | `true`, `false` |
| `watch.stable_window` | `10m` | положительная длительность, например `30s`, `10m`, `1h30m` |
| `explorer.enabled` | `true` | `true`, `false` |
| `explorer.everywhere` | `false` | `true`, `false` |
| `explorer.in_git` | `false` | `true`, `false` |
| `ui.language` | `auto` | `auto`, `en`, `zh-CN` |
| `ui.tray` | `true` | `true`, `false` |
| `ui.taskbar` | `true` | `true`, `false` |
| `update.check` | `true` | `true`, `false` |
| `telemetry.enabled` | `true` | `true`, `false` |
| `agent_shells` | не задана | таблица: имя агента = `bash` или `powershell` |
| `codex_windows_shell` | не задана | `bash`, `powershell` |

## Куда попадает то, что истекло

По умолчанию объект, у которого закончился срок жизни, попадает на кладбище Obituary. В течение `graveyard.retention_days` дней (7, если вы ничего не меняли) его можно вернуть на место командой `obit resurrect`, и только по истечении этого срока он удаляется навсегда. Число может быть любым от 1 до 3650.

Если задать `graveyard.mode` равным `recycle`, истёкшее отправляется в системную Корзину, дальше о нём заботится Windows. Этот режим есть только в Windows; в macOS и Linux есть лишь кладбище. То, что лежит в Корзине, восстанавливают из Корзины, а `obit resurrect` его не найдёт.

## Автоматическая регистрация и сеансы агентов

`proposals.mode` определяет, будет ли Obituary сам назначать файлам срок жизни. Значение по умолчанию, `off`, ничего не делает автоматически: попадает только то, что агент или вы регистрируете командами, через контекстное меню или правила для папок. В режиме `tiered` файлы, которые агент создал в этом сеансе, и контейнеры, запущенные сеансом, регистрируются сразу, а вы узнаёте об этом потом; снять объект с учёта можно командой `obit spare`. Всё остальное ждёт вашего одобрения в `obit proposals`. Режим `auto` регистрирует всё, что нашла автоматическая регистрация, и сообщает об этом потом. Режим `ask` сначала спрашивает про каждый элемент. В любом режиме файлы, которые уже отслеживает Git, а также зависимости, результаты сборки и кэши (`node_modules`, `dist`, `__pycache__` и подобные) никогда не регистрируются автоматически. Правила описаны в разделе [Какие файлы регистрируются](./auto-register).

`hooks.session_cleanup` включён по умолчанию. Ближе к концу каждого сеанса агенту сообщают, какие созданные им файлы не имеют срока жизни и не отслеживаются Git, и просят дать временным файлам срок жизни (`obit mark`) или похоронить их; результаты работы остаются. `hooks.session_summary` по умолчанию выключен; если его включить, то в начале сеанса агент также узнаёт, какие объекты проекта истекают в ближайшие 24 часа и что было похоронено недавно. Он выключен ради экономии токенов: агента и так предупреждают, когда он обращается к похороненному пути.

## Правила для папок и даты в Проводнике

`watch.stable_window` — это терпение правила для папки: новый файл должен оставаться неизменным столько времени, прежде чем его переместят, чтобы не унести то, что ещё скачивается. Значение записывается в формате длительности Go: число и суффикс `s`, `m` или `h`, которые можно соединять, как в `1h30m`; оно должно быть больше нуля.

Настройки `explorer.*` важны только в Windows. Obituary заставляет Проводник показывать дату погребения рядом с именем файла, не меняя само имя. По умолчанию это происходит в «Загрузках», на рабочем столе (включая вложенные папки) и в местах, которыми управляет правило для папки. Если включить `explorer.everywhere`, дату покажут и другие отслеживаемые места; рабочие каталоги Git исключены, пока вы не зададите `explorer.in_git` равным `true`; а `explorer.enabled = false` отключает всё полностью. См. [Правила для папок](./folder-policies).

## Интерфейс

`ui.language` задаёт язык командной строки, окна, значка в области уведомлений и контекстного меню. Пока есть только `en` и `zh-CN`. Значение `auto` смотрит на переменную окружения `OBIT_LANG`, затем на `LC_ALL`, `LC_MESSAGES` и `LANG`, и наконец на язык интерфейса системы. `ui.tray` показывает или скрывает значок в области уведомлений (в macOS это значок в строке меню); если он скрыт, фоновая очистка и проверка обновлений продолжают работать. `ui.taskbar` действует только в Windows и определяет, будет ли у открытого окна кнопка на панели задач.

## Проверка обновлений и статистика использования

Когда `update.check` включён, Obituary читает публичные сведения о выпусках на GitHub не чаще раза в сутки и не отправляет данных об использовании. Если он выключен, вы всё равно можете в любой момент выполнить `obit update --check`. `telemetry.enabled` управляет анонимной статистикой использования. Это отдельный переключатель, не связанный с проверкой обновлений: `obit config telemetry off` отключает только статистику и стирает на этом компьютере идентификатор установки и все ещё не отправленные отчёты. Подробности — в [политике конфиденциальности](./privacy).

## Какую оболочку использует агент в Windows

Защита удаления должна прочитать команду удаления, которую агент собирается выполнить, чтобы предложить равнозначную команду `obit`. В Windows агент может работать и в bash, и в PowerShell, а Obituary не может определить, в какой именно, поэтому об этом заявляете вы: этот агент работает на этом компьютере с Windows и в этой оболочке. Без такого заявления команды с неоднозначным смыслом проходят без блокировки.

```toml
[agent_shells]
codex = "powershell"
```

Ключи в `agent_shells` — это имена агентов. Сейчас эту таблицу читают `codex`, `codebuddy`, `codebuddy-ide` и `minimax-code`. `codex_windows_shell` — прежняя запись, только для Codex; если она и `agent_shells.codex` заданы с разными значениями, конфигурация отклоняется.

## Как выглядит ошибка

Obituary не игнорирует молча незнакомый ключ. Если бы игнорировал, при `retention = 30` продолжал бы действовать срок хранения в 7 дней, а вы думали бы, что он стал 30. Поэтому `obit config` сообщает путь к файлу, номер строки и полное имя нераспознанного ключа и, если написание близко, подсказывает правильный ключ:

```text
obit: config file has errors: …\config.toml:2: unknown key "graveyard.retention" (did you mean "graveyard.retention_days"?)
```

Значение вне допустимого диапазона сообщается так же: с названием настройки и тем, что она допускает, например `graveyard.retention_days must be between 1 and 3650`. Синтаксическая ошибка TOML тоже приводит к сбою `obit config`. Исправьте файл и запустите команду снова; когда она перестанет жаловаться, всё исправлено.

## Частые команды

```powershell
obit config                  # расположение файла, каталог данных и действующие значения
obit config --create         # записать файл по умолчанию с комментариями
obit config --language en    # сохранить язык интерфейса: auto, en или zh-CN
obit config telemetry off    # выключить статистику использования (on включает её снова)
```

`--create` никогда не перезаписывает существующий файл; если файл уже есть, команда сообщает об ошибке и останавливается. `--language` создаёт файл со значениями по умолчанию, если его ещё нет.
