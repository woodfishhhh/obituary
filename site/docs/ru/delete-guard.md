# Защита удаления

Удаление домашнего каталога или целого диска уже не является гипотезой. Если защита включена и агент запускает `rm -rf build`, `rmdir`, `git clean -fdx`, `Remove-Item -Recurse` или похожую команду, Obituary останавливает выполнение и сообщает эквивалентную команду, например `obit rm -rf build`. После её использования объекты попадают на кладбище, а не исчезают; `obit resurrect <id>` возвращает их.

```powershell
obit init -g --guard-rm                 # Claude Code; add --agent codex for Codex. Off by default
```

Защита от удаления распознаёт `docker volume rm`, `docker volume remove`, `docker volume prune`, `docker compose down -v` (или `--volumes`) и `docker system prune --volumes`. Замена на `obit bury --docker-volume` предлагается только для простой команды `docker volume rm` с явными именами.

Защита от удаления также останавливает `wsl --unregister` (включая `wsl.exe`, полные пути, запись с `=` и вызовы через `cmd /c` или `powershell -Command`), поскольку эта команда безвозвратно удаляет весь дистрибутив WSL и его виртуальный диск (`ext4.vhdx`). Obituary не хоронит и не воскрешает дистрибутивы WSL; в сообщении об отказе перед ручным подтверждением указывается резервное копирование через `wsl --export <distro> <backup.tar>`. Команды только для чтения и неразрушающие команды вроде `wsl --list`, `wsl --status`, `wsl --export`, `wsl --terminate` и `wsl --shutdown` проходят свободно.

## Реальный запуск

При включённой защите хук получил Bash-вызов Claude Code, `rm -rf build`, и ответил следующим образом; `rm` не выполнялась:

```json
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"Obituary's delete guard is on: `'C:/work/obit.exe' rm -rf build` provides restorable deletion; `obit resurrect` restores graveyard entries."}}
```

Затем агент переключается на Obituary: папка отправляется на кладбище и возвращается одной командой.

```console
$ obit rm -rf build
$ obit graveyard --here
ID  BURIED            PURGE  SIZE  PATH
#2  2026-11-11 00:36  in 7d  23 B  C:\work\build
$ obit resurrect --last
#2 resurrected  C:\work\build
```

## Принципы

- **Остановить, но не переписывать.** Obituary не меняет команду агента. Claude Code проверяет права для переписанной команды, поэтому правило `deny` для исходной может перестать действовать. Отклонение исходной команды и повторная выдача эквивалентной сохраняют все правила доступа.
- **Любое буквальное удаление останавливается.** `rm`, `rmdir`, `git clean` и `Remove-Item` (включая `del`, `rd`, `ri`) останавливают выполнение в любой позиции, после `&&`, `||` или `;`, в конвейере, `$(…)`, дочерней оболочке, условии или цикле. Это относится к `rm -rf build && npm run build`, `rm -rf build 2>/dev/null` и `git clean -fdx && npm ci`. `rm` внутри строк, комментариев и аргументов `echo` не считается; предварительные команды `rm --help`, `git clean -n`, `Remove-Item -WhatIf` тоже проходят.
- **Сначала перечисляйте цели, выбранные во время выполнения.** `find -delete`, `find -exec rm` (включая `-execdir`), `xargs rm` и PowerShell `Get-ChildItem … | Remove-Item` отклоняются без переписывания. Сначала проверьте совпадения, затем передайте явные пути команде `obit rm -- <path>...`. `find`, который только ищет или перечисляет пути, продолжает работать. Защита не проверяет произвольные оболочки вроде `sudo rm` или `bash -c '…'`.
- **Настоящее удаление не является запасным вариантом.** Каждый путь, переданный в `obit rm`, `obit remove-item` или `obit git-clean`, хоронится. При отказе формат ошибки соответствует `rm`, а код возврата ненулевой.
- **Проверяется реальный путь.** Между намерением агента и выполнением находятся кавычки, экранирование и иногда прокси. Один потерянный символ превращает `rm -rf "$OUT"/` в `rm -rf /`. Перед действием `obit rm` проверяет путь на диске.
- **В Windows Codex подстановки внутри кавычек тоже учитываются.** Другая оболочка может выполнить текст, который Bash считал бы буквальным. `$(…)` проверяется по правилам Bash и PowerShell, в том числе внутри кавычек, цитируемых heredoc и комментариев. Любое удаление останавливает выполнение; текст с обратными кавычками можно записать в файл и передать как путь.
- Файлы под управлением Git тоже хоронятся, чтобы незакоммиченные изменения можно было восстановить. Это намеренное удаление агентом, а не автоматическая регистрация.
- `obit rm -rf` для папки с `.git` хоронит весь репозиторий. Настоящая `rm -rf` уничтожила бы его, а захоронение можно отменить. Защита системных и пользовательских папок остаётся.
- **Эквивалентная команда намеренно ограничена.** Она не может выбирать больше исходной. Поэтому Obituary не переводит команды между оболочками и предлагает эквивалент только для форм из таблицы. В остальных случаях удаление останавливается, а `obit bury <path>` и `obit git-clean` указываются как восстанавливаемые альтернативы.

## Что останавливается и что проходит

| Среда | Остановка с эквивалентной командой | Остановка с причиной и общей рекомендацией | Пропуск |
|---|---|---|---|
| Claude Code (Bash) | `rm`, `rmdir`, `git clean`, при необходимости с буквальным `cd x` перед ними через `&&`, `;` или новую строку; `rm -f *.log`, если нет файла на `-`, `rm -rf ../dist`, `rm -- "$target"` с переменной после `--` | Любое другое буквальное удаление: другие команды (`npm …`, `trap`, `hash`), переменные до `--`, абсолютные POSIX-пути с начальным `/`, перенаправления, `\|\|`, конвейеры, `$(…)`, интерактивное удаление, `/usr/bin/rm` с путем | Команды без удаления |
| Codex в WSL, `/mnt/<drive>` | Одна команда `rm` или `rmdir` с относительными путями без `..`, `~`, подстановок и кавычек | Любое другое буквальное удаление, включая `git clean` и пути в собственную файловую систему WSL | Рабочий каталог в собственной файловой системе WSL |
| Codex с Windows PowerShell | Одна команда `Remove-Item` или псевдоним с буквальным путём (`-Recurse`, `-Force` разрешены) | Любое другое буквальное удаление: несколько команд, конвейеры, параметры вроде `-ErrorAction`, пути провайдера, `~`, подстановки и обратные кавычки | Текст в фигурных кавычках |
| Codex в Windows с неизвестной оболочкой | — | Удаление внутри необработанных фрагментов backtick или `$(…)` | Другие команды |
| pwsh в Linux, `git rm` | — | — | Всё проходит |

Чтобы предложить эквивалент, удаление должно быть **последним сегментом** команды; предыдущие сегменты соединяются только через `&&`, `;` или новые строки. Для имён, заканчивающихся точкой или пробелом, эквивалент не предлагается, потому что Windows нормализует их. Буквальное удаление всё равно останавливается.

## Используйте его сами

`obit rm`, `obit rmdir` и `obit git-clean` принимают обычные неинтерактивные параметры `rm`, `rmdir` и `git clean`. Неподдерживаемые параметры вроде `-i` или `rmdir -p` вызывают ошибку. `obit remove-item` — упрощённый вариант `Remove-Item`, принимающий только один буквальный путь; для подстановок используйте в Bash `obit rm *.log`.

Временно отключите защиту через `OBIT_GUARD_RM=0`. `obit stats` показывает число остановленных удалений и объём захороненного.
