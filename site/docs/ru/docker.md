# Контейнеры и тома Docker

Контейнеры, запущенные в сеансе агента, также могут иметь срок жизни.

```powershell
obit docker add web-1 3d       # register a container by name or ID; it expires in three days
obit docker list               # registered containers (--json works too)
obit resurrect <id>            # start a container that was stopped at expiry
```

## Назначить срок жизни сразу при запуске контейнера

Временные контейнеры чаще всего забывают остановить, когда срок не задан в момент запуска. Команда `docker run -d` выводит полный ID контейнера в стандартный вывод, и его можно сразу передать в `obit docker add`:

```powershell
# PowerShell
$cid = docker run -d --name tmp-redis redis:7
if ($LASTEXITCODE -eq 0) { obit docker add $cid 4h }
```

```bash
# Bash / zsh (no name required; pass the returned ID directly)
cid=$(docker run -d redis:7) && obit docker add "$cid" 4h
```

`obit docker add <name-or-id> <lifespan>` принимает имя контейнера, короткий ID или полный 64-символьный ID и не поддерживает флаги `--at` и `--note`. После регистрации команда выводит номер записи и время истечения (`#<id> docker:<name> (<12-char-id>)  expires <time>`). Не добавляйте `--rm` к `docker run`: Docker удаляет контейнеры с AutoRemove сразу после остановки, поэтому `obit docker add` отказывается их регистрировать. До истечения срока можно использовать номер из `obit docker list` или `obit list` с командами `obit extend <id> <lifespan>` и `obit spare <id>`.

## Проверить и воскресить остановленные контейнеры в период хранения

Когда срок жизни контейнера истекает и выполняется `docker stop`, он исчезает из `obit docker list` (где показаны только активные отслеживаемые контейнеры) и попадает на кладбище на срок `[graveyard] retention_days` (по умолчанию 7 дней). Просмотреть или вернуть остановленные контейнеры в этот период можно так:

```powershell
obit graveyard                 # list all restorable burials; containers show as docker:<name> (<12-char-id>) with purge countdown
obit graveyard --json          # machine-readable output; filter burials where kind == "container"
obit stats                     # total graveyard count and the next purge time
obit resurrect <id>            # start the stopped container by its numeric graveyard ID and stop tracking it
```

Контейнеры, зарегистрированные вручную через `obit docker add`, не привязаны к каталогу проекта и поэтому не попадают в выдачу `obit graveyard --here`; под `--here` попадают только контейнеры из автоматической регистрации или одобренного предложения проекта. На рабочем столе меню в трее показывает общее число записей на кладбище и до 10 последних похороненных объектов (нажатие сразу воскрешает запись), а на странице кладбища в окне программы можно искать по имени, видеть обратный отсчёт до удаления и воскрешать выбранные записи. Фоновый процесс не отправляет системные уведомления при остановке контейнера или перед окончательным удалением, поэтому для проверки остановленных контейнеров до конца срока хранения открывайте `obit graveyard` или страницу кладбища.

## Назначить тому срок или похоронить его сразу

Тома не регистрируются автоматически. Obituary обрабатывает только тома, которые вы явно зарегистрировали или похоронили, и не удаляет образы и сети.

Команда `obit mark --docker-volume cache 3d` (вместо `mark` можно написать `add`) назначает тому `cache` срок в три дня. Чтобы похоронить его сразу, выполните `obit bury --docker-volume -- cache`.

Docker должен работать в режиме контейнеров Linux. Поддерживаются только локальные тома с драйвером `local` без дополнительных параметров. При первом использовании Docker загружает вспомогательный образ Debian фиксированной версии, если его ещё нет.

На кладбище должно хватить места для полного архива. Том удаляется только после архивации и проверки. Если на том ссылается контейнер, даже остановленный, или путь пересекается с bind-монтированием, том остаётся на месте.

`obit resurrect <id>` создаёт том под исходным именем с постоянной меткой `io.obituary.restore`. Если имя уже занято, существующий том не перезаписывается, даже если он пуст.

До и после удаления проверяются события Docker. Если удаление не удалось подтвердить, сохраните проверенный архив и посмотрите вывод `obit doctor`: считать том успешно похороненным нельзя. Каждое предупреждение `docker-volume-recovery` указывает на запись, которую нужно проверить. Проверьте том на исходном демоне Docker согласно подсказке. Команды `obit resurrect` и `obit purge` не работают с архивом, не внесённым в реестр.

Защита от удаления распознаёт `docker volume rm`, `docker volume remove`, `docker volume prune`, `docker compose down -v` (или `--volumes`) и `docker system prune --volumes`. Замена на `obit bury --docker-volume` предлагается только для простой команды `docker volume rm` с явными именами.

## По истечении срока контейнер останавливается

- После `docker stop` контейнер и его слой для записи сохраняются. Команда `obit resurrect <id>` выполняет `docker start` и прекращает отслеживать срок жизни контейнера.
- Контейнер удаляется командой `docker rm` только после истечения срока хранения (`[graveyard] retention_days`, по умолчанию 7 дней). Параметры `-v` и `-f` никогда не используются.
- Если во время хранения вы запустите контейнер, Obituary сохранит его и прекратит отслеживание, даже если вы снова его остановите. Старые версии не записывали время запуска: такие контейнеры не удаляются, их по-прежнему можно восстановить командой `obit resurrect <id>`.
- Ни `obit purge`, ни `--all` не сокращают срок хранения контейнеров. Режим системной корзины к ним не применяется: контейнер сначала останавливают и лишь по истечении срока удаляют.

## Проверка по полному ID

- Имя служит только для отображения. Перед каждой остановкой, запуском или удалением Obituary сверяет полный ID и время создания с записью в реестре. При несовпадении операция не выполняется.
- Obituary запоминает контекст Docker и демон, которому принадлежит контейнер, и работает только с этим демоном. Смена `docker context` не перенаправит операцию.
- Если вы удалили контейнер вне Obituary, программа отмечает внешнее удаление и убирает запись из реестра.
- Контейнер с параметром `--rm` (AutoRemove) сам Docker удалит при остановке. Поэтому Obituary отказывается регистрировать такие контейнеры.

## Автоматическая регистрация контейнеров сеанса

По умолчанию автоматическая регистрация выключена. Obituary не ищет контейнеры; отдельный контейнер можно зарегистрировать командой `obit docker add`. Если включить регистрацию, в конце сеанса Obituary в фоновом режиме найдёт контейнеры, созданные за время сеанса. Учитываются лишь те, у которых рабочий каталог Compose или источник bind-монтирования находится внутри проекта. Остальные могли запустить в другом месте, поэтому их не трогают. Найденным контейнерам назначается срок жизни три дня; вы получите уведомление после регистрации. Если отменить её командой `obit spare <id>`, этот сеанс не зарегистрирует контейнер повторно. Если сеанс запущен вне Git-проекта (например, в домашнем каталоге) или на один контейнер претендуют несколько сеансов, установить его происхождение нельзя. Тогда создаётся только предложение, требующее вашего одобрения. В режиме `[proposals] mode = "ask"` также создаются предложения, а отслеживание начинается только после `obit approve`.

Для каждого контейнера создаётся не более одного предложения. Хуки никогда не вызывают Docker. Если Docker не установлен или не запущен, этот этап пропускается без уведомлений; причину показывает `obit doctor`. Пока Docker не работает, одобрить предложение по контейнеру нельзя. Об этом сообщают `obit proposals` и страница решений в окне программы. После запуска Docker предложение можно одобрить.
