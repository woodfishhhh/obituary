# Как работает Obituary

## Срок службы файла

1. **Зарегистрировать.** Задайте файлу или папке срок жизни. Агент использует `obit add debug.log 2h`, а вы можете выбрать «Add to Obituary» в контекстном меню Проводника. См. [что попадает в реестр](./auto-register).
2. **Дождаться истечения срока.** `obit list` показывает, сколько времени осталось. До истечения срока `obit extend` продлевает его, а `obit spare` прекращает отслеживание, оставляя файл на месте.
3. **Похоронить.** По истечении срока объект перемещается на кладбище (`obit graveyard`), где по умолчанию хранится семь дней.
4. **Воскресить или удалить навсегда.** Пока срок хранения не истёк, `obit resurrect <id>` возвращает объект на прежнее место, ничего не перезаписывая. Безвозвратное удаление (`obit purge`) происходит только после окончания этого срока.

Не уверены, понадобится ли ещё файл? Похороните его сейчас командой `obit bury`. Семь дней его можно будет воскресить в исходном виде.

## Расположение кладбища

Кладбище всегда находится на том же диске, что и файл. На диске с каталогом данных используется кладбище внутри этого каталога, на других дисках — скрытый каталог `.obituary` в корне. Поэтому захоронение сводится к переименованию: оно быстрое, и объект не может оказаться перемещённым лишь частично.

Срок хранения задаётся в настройках. Вместо кладбища можно отправлять объекты напрямую в системную корзину. Тогда восстанавливать их нужно из корзины, а не командой `obit resurrect`:

```toml
[graveyard]
mode = "graveyard"      # or "recycle": straight to the system Recycle Bin
retention_days = 7      # days the graveyard keeps things
```

Настройки находятся в `%APPDATA%\obituary\config.toml`. Команда `obit config` показывает их, а `obit config --create` записывает файл со значениями по умолчанию и комментариями.

## Почему не удаляются посторонние файлы

- **Безвозвратное удаление возможно только при очистке могилы.** Для каждого объекта создаётся отдельный каталог могилы; его файловый ID сохраняется. Перед окончательным удалением или воскрешением Obituary проверяет, что это тот же каталог, в нём ровно один элемент и это именно похороненный объект. Поэтому повреждение реестра или подмена кладбища ссылкой не приведут к удалению чего-либо за его пределами.
- **Воскрешение возможно только на прежнем месте.** Если имя занято, ничего не перезаписывается: объект возвращается рядом под именем вроде `name (resurrected).ext`. Сохраняются оба файла, а в результате операции указан фактический путь. Удалённый родительский каталог создаётся заново. Если вместо него появилась точка соединения или символическая ссылка, изменилась цель точки соединения либо буква диска стала указывать на другой том, воскрешение отклоняется и могила остаётся нетронутой.
- **Важен сам файл, а не его имя.** В каждой записи хранятся серийный номер тома и 128-битный ID файла. Это позволяет найти файл после перемещения или переименования и не тронуть другой файл по старому пути. Прямо перед удалением идентификаторы сверяются ещё раз. Файлы с несколькими жёсткими ссылками не принимаются.
- **Защищённые пути.** Корни дисков, `C:\Windows`, Program Files, ProgramData, профиль пользователя, рабочий стол, «Документы», «Загрузки» и аналогичные папки, а также их родительские каталоги защищены, в том числе при перенаправлении. Их содержимому можно задать срок жизни, самим папкам нельзя.
- **Репозитории Git.** Если внутри папки на любой глубине есть `.git`, командам `obit add` и `obit bury` нужен `--force`. По истечении срока проверка повторяется. Если её не удалось завершить, захоронение отклоняется.
- **При сомнении удаления не будет.** Запись снимается с отслеживания только при подтверждении, что файл уже отсутствует. При отказе в доступе, отключённом томе и подобных ошибках попытка повторяется позже. Интервал начинается с минуты и постепенно увеличивается до суток. После 12 неудач подряд Obituary останавливается и ждёт решения. Причина указана в `obit list` и в разделе «Burials that failed» на странице For you. `obit extend <id> 1m` («Retry») повторяет попытку, `obit spare <id>` («Stop tracking») оставляет объект на месте. Перед захоронением большой папки до 30 секунд отводится на поиск Git-репозиториев. Если проверка не завершилась, её повторят позже; похоронить можно только проверенную папку без репозиториев.
- **Все операции записываются.** Регистрация, продление, отмена и удаление попадают в журнал аудита (`obit log`).

## Работа в фоне

Когда в настольной версии включён надзор, процесс в трее обрабатывает записи по истечении срока, а отдельное задание проверяет их раз в час. Если для этого каталога данных надзор за процессом в трее не включён, задание запускается каждые пять минут.

В Windows процессом управляет задание при входе в систему, в macOS — пользовательский LaunchAgent, а в графическом сеансе Linux — пользовательская служба systemd. После сбоя процесс перезапускается через 60 секунд; после третьего сбоя за 15 минут попытки прекращаются.

Проверьте состояние задания командой `obit daemon status`. Чтобы обработать просроченные записи сразу, выполните `obit reap`.

```powershell
obit daemon enable              # tray at login plus the fallback scheduled task (--dry-run lists what would be installed)
obit daemon status              # current mode and the next expiry (--json)
obit daemon disable             # remove the scheduled task and login start, and stop the running daemon (--dry-run previews)
```

Запросы `list`, `graveyard`, `stats` и `log` работают только на чтение и ничего не хоронят.

## Где хранятся данные {#where-the-data-lives}

В `%LOCALAPPDATA%\obituary` находятся `store.json` (реестр), `audit.jsonl` (журнал аудита), `obitd.log` (журнал фонового процесса) и `graveyard\` (кладбище этого диска).

Изменить расположение позволяют `OBIT_HOME` (данные), `OBIT_CONFIG_DIR` (настройки) и `OBIT_USER_HOME` (домашний каталог).

При повторном запуске с тем же каталогом данных на передний план выходит уже открытое окно. С другим `OBIT_HOME` открывается отдельное окно. Если каталог отличается от стандартного, в заголовке виден его путь.
