# Удаление программы

Удаление состоит из двух шагов: сначала Obituary убирает то, что настроил, затем вы удаляете сами программы. Кладбище и реестр по умолчанию остаются, так что похороненные файлы можно воскресить и после удаления.

```powershell
obit uninstall --dry-run      # перечислить, что будет убрано, ничего не меняя
obit uninstall                # показать план и выполнить его после вашего подтверждения
```

Если вы устанавливали в Windows скриптом, достаточно одной команды:

```powershell
.\install.ps1 -Uninstall      # сам запустит obit uninstall --yes, затем удалит файлы программы, добавленную им запись PATH и свой ярлык в меню «Пуск»
```

## Что убирается

`obit uninstall` работает на уровне пользователя и в текущем Git-проекте: хуки, MCP и Skill каждого агента, плановое задание (Планировщик заданий в Windows, пользовательский агент launchd в macOS, пользовательский таймер systemd в Linux), постоянно работающий процесс и значок в области уведомлений, а также правила для папок (файлы под правилом остаются на месте). В Windows он также убирает запись автозапуска при входе, контекстное меню Проводника и метки дат в Проводнике.

Он трогает только то, что записал сам Obituary. Запись, которую вы изменили или которую оставила другая установка, сохраняется как есть, а в плане сказано, какая именно и почему. Там, где нет терминала (скрипт, командная строка агента), добавьте `--yes`; без него команда остановится и сообщит, что ей нужен терминал.

Три вещи он за вас не делает. Файлы программы удаляются способом, соответствующим тому, как вы устанавливали (см. ниже). Если вы устанавливали хуки уровня проекта в других проектах, выполните `obit uninstall` в каждом из них до удаления программ, иначе тамошние хуки перестанут работать, потому что `obit` исчезнет. И в macOS и Linux запись автозапуска значка в область уведомлений в список не входит: перед удалением выключите «Start the tray at sign-in» в Settings окна, и запись, которую создал Obituary, будет удалена. В Windows автозапуск значка обрабатывает сам `obit uninstall`, но ярлыки в меню «Пуск» и на рабочем столе, созданные `obit init`, в его список не входят; их удаляет `obit init --uninstall`, если не добавить `--no-shortcuts`.

## Кладбище, реестр и ваша конфигурация

По умолчанию сохраняются три вещи: файлы на кладбище, реестр с журналом аудита и `config.toml`. `obit uninstall` сообщает, сколько ещё лежит на кладбище и где, а при последующей переустановке всё это подхватывается снова. Если вы используете режим Корзины, истёкшее уже лежит в системной Корзине; удаление программы её не трогает, и восстанавливать нужно из Корзины, потому что `obit resurrect` до неё не дотягивается.

Если вы действительно хотите стереть всё, добавьте `--purge-data`:

```powershell
obit uninstall --purge-data
```

Сначала команда перечислит каждый объект на кладбище, а после вашего подтверждения плана удаления попросит подтвердить ещё раз. После этого, прежде чем что-либо убрать, Obituary проверяет всё, к чему собирается прикоснуться: принадлежит ли каталог данных ему самому, узнаёт ли он каждый файл в нём и может ли подтвердить папку кладбища и каждую очищаемую могилу. Если какая-то проверка не пройдена, он останавливается и сообщает, какая; кладбище, реестр и службы остаются как были, так что очистка никогда не бывает выполнена наполовину. Только когда все проверки пройдены, он безвозвратно удаляет эти файлы, затем реестр, журнал аудита и прочие файлы, которые ведёт Obituary. В скрипте `--yes --purge-data` вместе пропускают оба вопроса.

Удаляются только файлы, которые команда узнаёт. Другие файлы, ссылки или неизвестная Obituary вложенная папка останавливают проверку, и команда называет найденное. `config.toml` в очистку не входит никогда, и переносить его не нужно, даже когда он лежит в одной папке с реестром (так по умолчанию в macOS): после очистки в этой папке остаётся только `config.toml`. Если конфигурация лежит в другом месте, каталог данных удаляется целиком.

## Удаление программ

Как удалять программы, зависит от того, как вы их устанавливали.

| Установлено с помощью | Как удалить |
| --- | --- |
| Скрипт установки для Windows | `.\install.ps1 -Uninstall` |
| Scoop | `obit uninstall`, затем `scoop uninstall obituary` |
| winget | `obit uninstall`, затем `winget uninstall woodfishhhh.Obituary` |
| Окно для macOS (DMG) | `obit uninstall` и выключить «Start the tray at sign-in», затем перетащить Obituary.app из «Программ» в Корзину |
| Homebrew | `obit uninstall`, затем `brew uninstall --cask obituary` |
| `install.sh` в macOS или Linux | `obit uninstall`, затем удалить `obit` и `obitd` из `~/.local/bin` |
| Настольный пакет для Ubuntu (`.deb`) | выключить «Start the tray at sign-in» и выйти из значка в области уведомлений, затем `sudo apt remove obituary-desktop` |

Приложение для macOS и `.deb` для Ubuntu содержат собственный `obit`, но ни то ни другое не добавляет его в PATH. Если вы не устанавливали командную строку отдельно, перед удалением запустите его по полному пути: `/Applications/Obituary.app/Contents/MacOS/obit` для приложения, `/usr/libexec/obituary/obit` для `.deb`. `apt remove` удаляет программы из этой папки, но оставляет ваше кладбище, настройки и командную строку, установленную другим способом.

## Где лежат данные

| | Данные (реестр, кладбище, журналы) | Конфигурация (`config.toml`) |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\obituary` | `%APPDATA%\obituary` |
| macOS | `~/Library/Application Support/obituary` | та же папка |
| Linux | `~/.local/share/obituary` | `~/.config/obituary` |

В Linux, если заданы `XDG_DATA_HOME` или `XDG_CONFIG_HOME`, в каждом случае это папка `obituary` внутри соответствующего каталога. Переменные окружения `OBIT_HOME` и `OBIT_CONFIG_DIR` переносят данные и конфигурацию в другое место, а `obit config` показывает, какие из них используются. На диске, где лежит каталог данных, кладбище — это его папка `graveyard`; на других дисках это скрытая папка `.obituary` в корне диска, чтобы погребение всегда было переименованием в пределах одного диска, а не копированием.
