# Какие файлы регистрируются

## Агент и вы решаете, а Obituary хоронит вовремя

Агент и вы решаете, что попадает в Obituary (по умолчанию `[proposals] mode = "off"`):

- **Агент регистрирует свои результаты.** Для отладочных сценариев, журналов и снимков экрана он задаёт срок жизни командой `obit mark <path> 2d`, создаёт временное место командой `obit mktemp 1d`, а сомнительные объекты хоронит командой `obit bury`. `obit init` объясняет агенту эти правила.
- **Вы добавляете объекты через контекстное меню.** В Windows щёлкните правой кнопкой файл или папку в Проводнике, выберите «Add to Obituary», а затем срок 1, 7 или 30 дней либо «Bury now (recoverable)». См. [окно, область уведомлений и контекстное меню](./desktop).
- **Правила для папок** задают срок жизни папкам вроде «Загрузки». См. [правила для папок](./folder-policies).

Зарегистрированные объекты хоронятся по истечении срока и ещё семь дней доступны для воскрешения в исходном виде. Ничего другого автоматически не добавляется.

- **Уборка в конце сеанса.** Перед остановкой агента Claude Code или Codex Obituary перечисляет файлы, созданные в этом сеансе и ещё не разобранные. Агенту предлагается задать срок жизни или похоронить отладочные сценарии, журналы и снимки экрана, сохранив результаты работы. Уведомление появляется не более одного раза за сеанс и отсутствует при пустом списке; другие агенты получают его в начале следующего сеанса. Отключить его можно параметром `[hooks] session_cleanup = false`.
- **При обновлении со старой версии** настройка один раз выключается. Ранее автоматически зарегистрированные зависимости, результаты сборки и кэши остаются на месте без срока жизни.

## Включите автоматическую регистрацию, когда вы хотите

Включите режим в Settings или For you либо задайте `[proposals] mode` в `config.toml`.

- `"tiered"` напрямую регистрирует файлы, созданные агентом в этом сеансе, и [контейнеры Docker](./docker), запущенные для проекта. Файл регистрируется напрямую, только если хук видел запись, файл отсутствовал в начальном снимке, а время создания позже начала сеанса. После регистрации агент получает уведомление, запись появляется в `obit proposals` и в разделе «Handled automatically» страницы For you. Уже существовавшие файлы и файлы, запись которых хук не видел, становятся только предложениями. `obit approve <id>` регистрирует предложенные объекты; после этого совпадающие правила проекта могут регистрировать объекты напрямую. `obit reject <id>` запрещает автоматическую регистрацию в этом проекте.
- `"auto"` напрямую регистрирует всё найденное автоматической регистрацией и сообщает вам после этого.
- `"ask"` сначала превращает всё в предложения и ждёт одобрения.

```powershell
obit proposals           # proposals waiting for you, and what was registered without asking
obit approve 3           # approve: register what it lists
obit reject 3            # reject
obit spare 12            # undo an automatic registration: it stays where it is, without a lifespan
obit extend 12 1w        # keep it longer
```

- **Зависимости, результаты сборки и кэши** (`node_modules`, `dist`, `.turbo`, `__pycache__` и тому подобное) не регистрируются и не предлагаются автоматически ни в одном режиме. Для очистки зарегистрируйте их сами командой `obit mark`.
- **Большие объекты**, созданные не агентом, тоже становятся предложениями, если занимают более 1 ГБ или содержат более 200 файлов.
- **Разница сеанса.** В начале делается снимок, который хранится в каталоге данных и не добавляется в репозиторий; в конце его сравнивают. Совпадения правил обрабатываются выбранным режимом, новые файлы без подходящего правила не регистрируются и не предлагаются.
- **После смены режима** фоновый процесс заново классифицирует ожидающие предложения.
- **Перед захоронением Git проверяется ещё раз.** Объект, зарегистрированный правилом или предложением, не хоронят, если к моменту истечения он уже попал в коммит.
- **Предложения истекают сами.** Зафиксированные в коммите или удалённые объекты убираются из предложения; пустое предложение отзывается, записывается в журнал аудита и не считается отказом.

Тома не регистрируются автоматически. Obituary обрабатывает только тома, которые вы явно зарегистрировали или похоронили, и не удаляет образы и сети.

## Правила

```powershell
obit rules                       # the rules in effect here (built-in plus a trusted .obitrules)
obit rules check debug.log out/  # preview what would be registered and by which rule (changes nothing)
obit rules apply debug.log       # register by rule
```

`obit rules apply` в любой момент регистрирует объект по правилам; при включённой автоматической регистрации хуки используют их тоже. Встроенные правила охватывают обычный мусор агента: `.playwright-mcp/`, `test-results/`, `*.log` и другое. Резервные копии `*.bak`, `*.bak.*`, `*.orig`, `*.rej`, `*.old`, `*.backup` и `*~` хранятся семь дней, а `LOG.old` LevelDB не трогают. Файл `.obitrules` в корне проекта использует синтаксис `.gitignore` и указывает срок после каждого шаблона.

```
output/**        7d      # every item under output gets its own lifespan
!output/keep/**          # never touch (negation wins, even over registering a parent folder)
test-results/    off     # turn off a built-in rule
```

В отличие от `.gitignore`, отрицания имеют приоритет над последним совпадением. В Windows регистр букв не учитывается. Неверный шаблон, например незакрытый `[`, указывает имя файла и строку и приостанавливает автоматическую регистрацию проекта.

Единицы времени: `s`, `m`, `h`, `d` и `w`; их можно сочетать, например `1d12h`.

## Жесткие правила автоматической регистрации

- Регистрируются только неотслеживаемые объекты внутри рабочего дерева Git.
- Папка, содержащая хотя бы один отслеживаемый файл, не затрагивается.
- Если Git не отвечает, объект пропускается.
Уже заданный срок жизни никогда не сокращается.
- Отклонённый проект ни в одном режиме не регистрируется напрямую. Применение правил для папок и доверие к `.obitrules` всегда требуют вашего решения.

## Правила проекта должны быть доверенными в первую очередь

Собственный `.obitrules` репозитория не действует, пока вы не проверите его и не выполните `obit trust`. Это не позволяет чужому репозиторию использовать правила для ваших личных файлов. При доверии сохраняется SHA-256 файла; любое изменение требует новой проверки. В неинтерактивном сеансе нужен `--yes`, а в CI можно задать `OBIT_TRUST_PROJECT_RULES=1`.

## Временная папка, которая погребает себя

```powershell
$dir = obit mktemp 1d            # .obit/tmp/ in a project (not in Git), otherwise the system temp folder
```

В bash: `dir=$(obit mktemp 1d)`.
