# 讣告怎么运作

## 一个文件的一生

1. **登记**：给文件或文件夹一个寿命。手动 `obit add debug.log 2h`，或者按规则[自动登记](./auto-register)。
2. **到期**：`obit list` 看谁还剩多久。到期之前可以 `obit extend` 续命，也可以 `obit spare` 饶它一命（不再跟踪，文件保留）。
3. **下葬**：寿命一到，东西被收进墓地（`obit graveyard` 查看），默认保留 7 天。
4. **复活或火化**：保留期内 `obit resurrect <编号>` 放回原处，绝不覆盖已有文件；保留期过后火化（`obit purge`），这才是真正删除。

拿不准有没有用的东西，可以直接 `obit bury` 先下葬：七天之内原样放得回来。

## 墓地在哪里

墓地和东西在同一块盘上：数据目录所在的盘用数据目录里的墓地，其他盘用该盘根目录下隐藏的 `.obituary`。所以下葬只是改名，又快又不会只搬了一半。

保留天数在配置里改。也可以配置成直接进系统回收站，这时要从回收站恢复，`obit resurrect` 救不回来：

```toml
[graveyard]
mode = "graveyard"      # 或 "recycle"：直接进系统回收站
retention_days = 7      # 墓地保留天数
```

配置文件是 `%APPDATA%\obituary\config.toml`，`obit config` 可以查看，`obit config --create` 生成带注释的默认配置。

## 为什么删不到别的东西

- **火化是唯一的永久删除。** 每次下葬都新建一个坟墓目录，并记下它的文件 ID。火化和复活之前都要核对：这个坟墓目录还是当初那个，里面只有一项，而且就是当初埋进去的对象。所以账本被改坏了、墓地被换成了链接，也删不到墓地以外的东西。
- **复活只回原处。** 原处已经有同名的东西时，不覆盖它，改名放在旁边（`名字 (resurrected).扩展名`），两份都保留，回执里写着实际放回的路径。上级目录被删了，复活会重建；上级目录变成了 junction / 符号链接、原本的 junction 被改指、盘符换了卷，都拒绝复活（墓地原样保留）。
- **认文件，不认文件名。** 每条记录都存着卷序列号和 128 位文件 ID：文件改名或移动了照样找得到；原路径上换成了别的文件，就不碰它。删除前再核对一次身份。有多个硬链接的文件一律拒绝。
- **受保护路径。** 盘符根目录、`C:\Windows`、Program Files、ProgramData，以及用户目录、桌面、文档、下载等文件夹本身和它们的上级目录都拒绝（被重定向到别处的也算）。这些文件夹里面的东西可以设。
- **Git 仓库。** `obit add`、`obit bury` 一个任何一层含 `.git` 的文件夹都要加 `--force`；到期时会再查一次，查不完也拒绝。
- **不确定就不删。** 只有确定文件已经不在了才放弃这条记录。拒绝访问、卷被拔掉这类情况一律稍后重试。
- **全程留痕。** 每次添加、续期、取消、删除都写进审计日志（`obit log`）。

## 后台运行

默认是托盘常驻：`obitd.exe` 随登录启动，到期精确到秒，托盘图标是它唯一的界面。另外保留一个 Windows 任务计划，每 5 分钟（以及每次登录时）运行一次 `obitd --once` 作兜底：托盘退出或没启动时，到期的东西照样会被收走、过了保留期的照样火化。agent 的 hook 在会话开始和结束时也会顺手处理一轮；`obit reap` 立即处理。

```powershell
obit daemon enable              # 托盘随登录启动，并装兜底的定时任务（--dry-run 只列出要装什么）
obit daemon status              # 现在是哪种模式、下一次到期（支持 --json）
obit daemon disable             # 撤掉定时任务和登录启动，并停掉正在运行的常驻进程（--dry-run 只预览）
```

`list`、`graveyard`、`stats`、`log` 这类查询只读，不会顺手下葬。

## 数据放在哪里

数据放在 `%LOCALAPPDATA%\obituary`：`store.json`（账本）、`audit.jsonl`（审计日志）、`obitd.log`（后台进程日志）、`graveyard\`（这块盘的墓地）。

可以用环境变量 `OBIT_HOME`（数据目录）、`OBIT_CONFIG_DIR`（配置目录）、`OBIT_USER_HOME`（用户主目录）换位置。
