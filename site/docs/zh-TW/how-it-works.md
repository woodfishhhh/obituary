# 訃告怎麼運作

## 一個檔案的一生

1. **登記**：為檔案或資料夾設定壽命。agent 可用 `obit add debug.log 2h`，你則可在檔案總管的右鍵選單中選「放進訃告」。詳見[哪些項目會納入訃告](./auto-register)。
2. **到期**：`obit list` 會顯示剩餘時間。到期前可用 `obit extend` 延長壽命，或用 `obit spare` 停止追蹤，把檔案留在原處。
3. **下葬**：到期後，項目會移入墓地（用 `obit graveyard` 查看），預設保留 7 天。
4. **復活或永久刪除**：保留期內，`obit resurrect <编号>` 可把項目放回原處，不會覆寫現有檔案。保留期過後才會永久刪除（`obit purge`）。

拿不準有沒有用的東西，可以直接 `obit bury` 先下葬：七天之內原樣放得回來。

## 墓地在哪裡

墓地和檔案位於同一個磁碟區。如果檔案和資料目錄在同一個磁碟機上，就使用資料目錄中的墓地；其他磁碟機則使用根目錄下隱藏的 `.obituary`。下葬只需重新命名，速度快，也不會只搬完一半。

保留時間可在設定中調整。你也可以讓項目直接進入系統的資源回收筒；這時須從資源回收筒還原，不能用 `obit resurrect`：

```toml
[graveyard]
mode = "graveyard"      # 或 "recycle"：一般檔案進系統資源回收筒，目錄進訃告墓地
retention_days = 7      # 墓地保留天數
max_size = ""           # 可選容量上限，如 "5GB"；超限時依最早下葬順序自動刪除，單件超限則留在原處等你決定
```

設定檔位於 `%APPDATA%\obituary\config.toml`。`obit config` 可顯示設定，`obit config --create` 則會寫入附有註解的預設設定檔。

## 為什麼不會誤刪其他項目

- **只有清除墓地項目才會永久刪除。** 每次下葬都會建立獨立的墳墓資料夾，記錄該資料夾的檔案 ID。永久刪除或復活前，訃告會確認它仍是原來的資料夾，裡面恰好有一個項目，而且正是當初下葬的物件。因此即使帳本損毀、墓地被換成連結，也不能刪到墓地外的東西。
- **只在原來的位置復活。** 遇到同名檔案時不會覆寫，復活的項目會另取名稱（`名字 (resurrected).扩展名`）放在旁邊，兩份都保留，執行結果會顯示實際路徑。上層資料夾遭刪除時會重建；若上層變成接合點或符號連結、接合點的目標已改變，或磁碟機代號現在指向另一個磁碟區，便拒絕復活，保留墓地原狀。
- **辨識檔案本身，而不是檔名。** 每筆紀錄都保存磁碟區序號和 128 位元檔案 ID；即使檔案改名或移動，仍能找到它，不會動到佔用舊路徑的其他檔案。刪除前會再核對一次身分。若檔案有多個硬連結，就拒絕操作。
- **受保護的路徑。** 磁碟機根目錄、`C:\Windows`、Program Files、ProgramData，以及使用者設定檔、桌面、文件、下載等資料夾本身和它們的上層目錄都受保護，即使曾重新導向也一樣。這些資料夾內的項目仍可設定壽命。
- **Git 儲存庫。** 只要資料夾內任何深度有 `.git`，執行 `obit add` 或 `obit bury` 都需要 `--force`。到期時會再次檢查；檢查無法完成便拒絕下葬。
- **無法確定就不刪除。** 只有確定檔案已不存在時才放棄該筆紀錄。存取遭拒、磁碟區已拔除等情況會稍後再試。間隔從 1 分鐘逐漸增加，最長一天；連續失敗 12 次後便停止，等你處理。可在 `obit list` 和小視窗「待你決定」頁的下葬失敗清單查看原因。`obit extend <编号> 1m`（視窗中的「重試」）會再次嘗試，`obit spare <编号>`（「停止追蹤」）則讓項目留在原處。大型資料夾下葬前會先搜尋最多 30 秒，確認是否含有 Git 儲存庫。檢查未完成便稍後再試；有儲存庫的資料夾不會下葬。
- **每項操作都有紀錄。** 新增、延長壽命、取消登記和刪除都會寫入稽核日誌（`obit log`）。

## 背景執行

桌面版啟用監督後，由常駐托盤在到期時處理，另有獨立工作每小時檢查一次。資料目錄未啟用系統匣監督時，每 5 分鐘檢查一次。

Windows 由登入時啟動的排程工作看管托盤，macOS 使用使用者 LaunchAgent，Linux 則使用圖形工作階段的使用者 systemd 服務。異常結束後等 60 秒重新啟動；15 分鐘內第三次異常結束就停止重試。

agent hook 在工作階段開始與結束時也會執行一次清理；`obit reap` 可立即執行。

```powershell
obit daemon enable              # 托盘随登录启动，并装兜底的定时任务（--dry-run 只列出要装什么）
obit daemon status              # 现在是哪种模式、下一次到期（支持 --json）
obit daemon disable             # 撤掉定时任务和登录启动，并停掉正在运行的常驻进程（--dry-run 只预览）
```

`list`、`graveyard`、`stats` 和 `log` 等查詢指令都是唯讀，不會觸發下葬。

## 資料放在哪裡 {#storage}

`%LOCALAPPDATA%\obituary` 存放 `store.json`（帳本）、`audit.jsonl`（稽核日誌）、`obitd.log`（背景程式日誌）及 `graveyard\`（這個磁碟機的墓地）。

可用 `OBIT_HOME` 指定資料目錄、`OBIT_CONFIG_DIR` 指定設定目錄、`OBIT_USER_HOME` 指定使用者家目錄。

再次開啟小視窗會切回同一資料目錄的視窗。使用不同的 `OBIT_HOME` 啟動會另開視窗；非預設目錄的路徑會顯示在標題中。
