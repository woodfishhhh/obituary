# 哪些項目會納入訃告

## agent 和你決定，訃告按時下葬

預設由你和 agent 決定要登記哪些項目（`[proposals] mode = "off"`）：

- **agent 自行登記產出。** 它用 `obit mark <路径> 2d` 為自己寫的除錯指令稿、日誌和截圖設定壽命，用 `obit mktemp 1d` 建立暫存資料夾，拿不準要不要保留的項目則用 `obit bury` 下葬。`obit init` 寫給 agent 的說明中列有這些做法。
- **你可以從右鍵選單加入。** 在 Windows 的檔案總管中，對檔案或資料夾按右鍵（可多選），選「放進訃告」，再選 1、7 或 30 天，也可以選「現在埋掉（可恢復）」。詳見[小視窗、系統匣與右鍵選單](./desktop)。
- **資料夾策略**：給下載這類資料夾設一個壽命，見 [資料夾策略](./folder-policies)。

已登記的項目到期便下葬，接下來 7 天內都可以從墓地原樣復活。其他項目不會自行加入。

- **工作階段結束時整理。** Claude Code 或 Codex 即將停止時，訃告會列出該 agent 在這次工作階段建立但尚未分類的檔案，請它為除錯指令稿、日誌和截圖設定壽命或下葬，保留正式成果。每次工作階段最多提醒一次，沒有待整理的項目便不提醒。其他 agent 會在下次工作階段開始時收到提醒。`[hooks] session_cleanup = false` 可停用這項功能。
- **從舊版本升級時**，訃告會把自動登記關閉一次；之後仍以你的設定為準。先前自動登記的依賴套件、建置輸出和快取會取消登記，留在原處，不再計時。

## 需要時開啟自動登記

在小視窗「設定」或「待你決定」頁切換，或在 `config.toml` 裡設 `[proposals] mode`：

- `"tiered"`（分級）：直接登記 agent 在本次工作階段建立的檔案，以及這次為專案啟動的 [Docker 容器](./docker)。檔案必須同時符合三個條件：hook 看到 agent 寫入、開始時的快照中沒有該檔案、檔案系統的建立時間在工作階段開始後。訃告會在登記後通知 agent，並列在 `obit proposals` 和「待你決定」頁的「已自動處理」中。原本已存在或 hook 未看到 agent 寫入的檔案只會列為提議。`obit approve <id>` 會登記提議所列項目，之後該專案中符合規則的項目便可直接登記；`obit reject <id>` 表示不再自動登記此專案的項目。
- `"auto"`（全自動）：自動登記找到的東西都直接進，事後告訴你。
- `"ask"`（全部都問）：都先列成提議。

```powershell
obit proposals           # 等你点头的提议，和没问你就登记了的东西
obit approve 3           # 同意：登记里面列的东西
obit reject 3            # 拒绝
obit spare 12            # 撤回一项自动登记：东西留在原处，不再计时
obit extend 12 1w        # 留久一点
```

- **依賴套件、建置輸出和快取**（`node_modules`、`dist`、`.turbo`、`__pycache__` 等）在任何模式下都不會自動登記，也不會產生提議。需要清理時請自行用 `obit mark` 登記。
- **大型項目**若不是 agent 建立的，超過 1 GB 或包含超過 200 個檔案時，也要先提議。
- **比對工作階段前後的差異。** 開始時建立快照，保存在資料目錄中，不往儲存庫新增檔案；結束時再比對。符合規則的項目依目前模式處理；不符合任何規則的新檔案既不登記也不提議。
- **切換模式後**，背景程式會按新模式重新處理尚待決定的提議。
- **下葬前再問一次 Git**：按規則或提議登記的東西，到期時如果已經被提交，就不下葬。
- **提議會自動失效。** 已提交或刪除的項目會從提議中移除。清單變空時會撤回提議，記入稽核日誌，但不算作你拒絕。

資料卷不會自動登記。訃告只處理你明確登記或下葬的資料卷，不會刪除映像檔或網路。

## 規則

```powershell
obit rules                       # 当前项目生效的规则（内置规则 + 已信任的 .obitrules）
obit rules check debug.log out/  # 预览：会登记什么、按哪条规则（不做任何改动）
obit rules apply debug.log       # 按规则登记
```

`obit rules apply` 可隨時依規則登記項目。開啟自動登記後，hook 也會使用這些規則。內建規則涵蓋 agent 常見的暫存產物，例如 `.playwright-mcp/`、`test-results/` 和 `*.log`。編輯留下的備份（`*.bak`、`*.bak.*`、`*.orig`、`*.rej`、`*.old`、`*.backup`、`*~`）會保留 7 天，但不會動到 LevelDB 的 `LOG.old`。專案根目錄的 `.obitrules` 使用 `.gitignore` 語法，每個模式後面加上壽命：

```
output/**        7d      # output 下的每一项单独计算寿命
!output/keep/**          # 永远不碰（否定规则优先，连上级目录都不会被整体登记）
test-results/    off     # 关掉某条内置规则
```

和 `.gitignore` 不同，排除規則優先，不是以最後一條符合的規則為準。在 Windows 上，比對不分大小寫。無效的模式（例如未閉合的 `[`）會產生錯誤，指出檔案和行號，並暫停該專案的自動登記。

時長單位：`s` `m` `h` `d` `w`，可以組合（`1d12h`）。

## 自動登記的硬規則

- 只登記 Git 工作區裡、沒有被 Git 跟蹤的東西。
- 資料夾只要包含一個受 Git 追蹤的檔案，就不會自動處理整個資料夾。
- Git 回答不了時一律跳過。
- 已經有壽命的不會被改短。
- 任何模式都不會直接登記你已拒絕的專案；資料夾策略和信任 `.obitrules` 一律由你決定。

## 專案規則要先信任

儲存庫內的 `.obitrules` 要等你審查並執行 `obit trust` 後才會生效，別人的儲存庫就無法用規則移走你的私人檔案。信任時會記錄檔案的 SHA-256；內容一旦改變，就須重新審查。非互動式工作階段需要 `--yes`；在 CI 中可設定 `OBIT_TRUST_PROJECT_RULES=1`。

## 會自己下葬的臨時目錄

```powershell
$dir = obit mktemp 1d            # 项目里放在 .obit/tmp/（不进 Git），否则放在系统临时目录
```

bash 裡寫 `dir=$(obit mktemp 1d)`。
