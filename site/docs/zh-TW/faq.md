# 常見問題

## 為什麼不直接刪？

還不確定要不要保留的檔案，一旦刪除就拿不回來。訃告會先把它下葬到墓地，預設保留 7 天；期間隨時可以用 `obit resurrect` 放回原處，過了保留期才永久刪除。如果 agent 在這七天內用到它，訃告會立即告知墓地編號和復活指令（見[墓地提醒](./grave-notices)）。

## 支援 macOS 和 Linux 嗎？

支援。macOS 和 Linux 都提供 x64／ARM64 命令列工具與背景程式，支援墓地、復活及自動下葬。macOS 用 launchd、Linux 用 systemd 使用者計時器檢查到期項目；agent hook 也會在需要時啟動檢查。詳見[快速開始](./index)。 Windows 和 Linux 可將 `graveyard.mode` 設為 `recycle`。請從系統資源回收筒還原，不能用 `obit resurrect`。macOS 僅支援墓地。

## 下載時 Windows 說「已保護你的電腦」？

訃告目前尚未簽署程式碼。如果用瀏覽器下載壓縮檔時看到警告，請選「其他資訊 → 仍要執行」。Scoop、winget 和安裝指令稿通常不會觸發這個提示，三者都會先核對壓縮檔的 SHA-256。

## ARM64 上有小視窗嗎？

沒有。`obit-gui.exe` 只有 x64 版；ARM64 版提供命令列和系統匣。

## 尚未提交的程式碼會被自動登記嗎？

不會。自動登記預設關閉，只有 agent 用 `obit mark` 登記的項目，以及你從右鍵選單加入的項目才會納入。即使開啟自動登記，也只處理 Git 工作樹內未受追蹤的項目。不符合任何規則的新檔案（例如尚未提交的程式碼）不會列入，依賴套件、建置輸出和快取也不會被動到。經由規則或提議登記的項目，若在到期時已提交，就不會下葬。詳見[哪些項目會納入訃告](./auto-register)。

## Git 出錯或 `.gitignore` 涵蓋的範圍很廣，會怎樣？

訃告會先向 Git 確認項目是否已受追蹤；若 Git 無法回應（未安裝、逾時或儲存庫損毀），就不會登記。Git 儲存庫以外的資料夾絕不自動登記，只有你或 agent 才能用 `obit mark` 手動設定壽命。`.gitignore` 涵蓋的範圍再廣，也只是讓更多項目不受追蹤；自動登記仍只適用內建規則及你已信任的 `.obitrules`。

## agent 能把我的檔案當作自己的，跳過提議嗎？

不行。自動登記預設關閉，沒有你的同意就不會自動納入。啟用分級模式後，只有能證明是 agent 在本次工作階段建立的檔案才會直接登記：hook 觀察到 agent 寫入、開始時的快照沒有該檔案，且檔案系統記錄的建立時間晚於工作階段開始時間。原本就存在或由其他程式建立的檔案，仍須先提議。即使 agent 被誘導將舊資料夾改成符合規則的名稱，建立時間也沒變，所以仍只會產生提議。任何模式都不會自動登記 Git 已追蹤的檔案；所有直接登記的項目都會事後通知，可用 `obit spare` 一次撤銷，下葬後七天內仍可復活。

## agent 能替我批准提議嗎？

不能。MCP 沒有核准或拒絕提議、信任 `.obitrules`、永久刪除墓地項目或變更設定（包括提議模式）的工具。agent 只能把提議轉交給你。

## 開啟資源回收筒模式後，還能用 `obit resurrect` 嗎？

不能。在 `config.toml` 中設定 `mode = "recycle"` 後，下葬的項目會移入系統的資源回收筒，要從那裡還原。

## 怎麼臨時關掉？

- hook：`OBIT_DISABLED=1`
- 刪除護欄：`OBIT_GUARD_RM=0`
- 自動清理：托盤選單裡「暫停」

## 資料放在哪裡？

`%LOCALAPPDATA%\obituary` 存放帳本、稽核日誌、背景程式日誌及這個磁碟機的墓地。設定檔位於 `%APPDATA%\obituary\config.toml`。詳見[運作方式](./how-it-works#storage)。

## 解除安裝會刪掉墓地嗎？

不會。`obit uninstall` 預設保留墓地和帳本，只有確定要一併刪除時才加上 `--purge-data`。詳見[解除安裝](./uninstall)。
