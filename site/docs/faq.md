# 常见问题

## 为什么不直接删？

拿不准有没有用的东西，删了就回不来。讣告先把它下葬进墓地，默认保留 7 天，期间随时 `obit resurrect` 放回原处；过了保留期才真正删除。七天里 agent 要是又用到它，讣告会当场告诉它编号和复活命令（见[墓地提醒](./grave-notices)）。

## 支持 macOS 和 Linux 吗？

支持，macOS 和 Linux 都提供 x64 / ARM64 命令行与后台程序，支持墓地、复活和自动下葬。macOS 通过 launchd、Linux 通过 systemd 用户定时器检查到期文件，agent hook 也会按需启动检查。安装方法见[快速开始](./index)。回收站模式、小窗口、托盘和右键菜单由 Windows 版提供。

## 下载时 Windows 说「已保护你的电脑」？

讣告还没有代码签名。用浏览器手动下载压缩包时可能会弹出这个提示，点「更多信息 → 仍要运行」即可；Scoop、winget 和安装脚本一般不会遇到。三种安装方式都会先核对 SHA-256。

## ARM64 上有小窗口吗？

没有。小窗口 `obit-gui.exe` 目前只有 x64 版；ARM64 版只有命令行和后台托盘。

## 会不会把我还没提交的代码登记走？

自动登记只登记 Git 工作区里、没有被 Git 跟踪的东西，并且规则覆盖不到的遗留物只提议、不登记，因为新出现的未跟踪文件可能是你还没提交的代码。按规则或提议登记的东西，到期时如果已经被提交，就不下葬。见[自动登记与提议](./auto-register)。

## Git 出问题、或者 `.gitignore` 写得很宽，会不会误伤？

不会。讣告每次登记前都要问 Git 这个东西有没有被跟踪，问不到（没装 Git、超时、仓库损坏）就不登记；不在 Git 仓库里的目录根本不会自动登记，只能由你或 agent 用 `obit mark` 手动设寿命。`.gitignore` 写得再宽也只是让更多东西变成「未跟踪」，自动登记仍然只认内置规则和你信任的 `.obitrules` 里列出的那几类，别的遗留物只会列成提议，等你点头。

## agent 能替我批准提议吗？

不能。批准或拒绝提议、信任 `.obitrules`、火化墓地、改配置，MCP 里都没有对应的工具，agent 只能把提议的内容转述给你。

## 配置成回收站模式之后还能 `obit resurrect` 吗？

不能。`config.toml` 里设了 `mode = "recycle"` 时，下葬进的是系统回收站，要从回收站恢复。

## 怎么临时关掉？

- hook：`OBIT_DISABLED=1`
- 删除护栏：`OBIT_GUARD_RM=0`
- 自动清理：托盘菜单里「暂停」

## 数据放在哪里？

`%LOCALAPPDATA%\obituary`：账本、审计日志、后台进程日志和这块盘的墓地。配置是 `%APPDATA%\obituary\config.toml`。见[讣告怎么运作](./how-it-works#数据放在哪里)。

## 卸载会删掉墓地吗？

不会。`obit uninstall` 默认保留墓地和账本，确实不要了再加 `--purge-data`。见[卸载](./uninstall)。
