# 自动登记与提议

## AI 自己的东西直接进，你的东西先问你

讣告默认按「分级」处理自动登记（`[proposals] mode = "tiered"`）。下面三类直接进讣告，不再等你拍板，事后告诉 agent，也列在 `obit proposals` 和小窗口「待你决定」的「已自动处理」里：

1. **agent 这次会话自己新建的文件**：hook 看着它写的，会话开始时没有它，文件系统记的创建时间也在会话开始之后。规则认得的按规则的寿命登记。
2. **能重新生成的东西**：会话留下的、被 Git 忽略的依赖目录、构建输出和缓存（`node_modules`、`dist`、`.turbo` 等），3 天到期。
3. **会话里为这个项目起的 Docker 容器**，见 [Docker 容器](./docker)。

不是 agent 建的才列成提议：会话开始前就在的文件，或者 hook 没看到 agent 写的文件。agent 会把提议转告你；你同意后执行 `obit approve <id>`，此后这个项目里规则认得的东西都直接登记；`obit reject <id>` 则表示以后别再自动登记这个项目。

```powershell
obit proposals           # 等你点头的提议，和没问你就登记了的东西
obit approve 3           # 同意：登记里面列的东西
obit reject 3            # 拒绝
obit spare 12            # 撤回一项自动登记：东西留在原处，不再计时
obit extend 12 1w        # 留久一点
```

想完全交给 AI，在小窗口「待你决定」页一键切到「全自动」，或者在 `config.toml` 里设 `[proposals] mode = "auto"`：自动登记找到的东西都直接进，事后告诉你。想回到什么都先问，设 `"ask"`。切换之后，还在等你的提议由后台按新模式重新分一次。

- **超大的东西**（超过 1 GB 或 200 个文件）不是 agent 新建的，照样先提议。
- **会话差分**：会话开始时记一份快照（存在数据目录，不往你的仓库里放东西），结束时对比。规则覆盖的东西照常处理；规则覆盖不到的，只有 Git 忽略、又能重新生成的东西才会被登记。没被 Git 忽略的新文件是你还没提交的代码，`.env` 这类被忽略的本地配置也不能重新生成，这两类都不会被自动登记，也不会出现在提议里。
- **收工整理**：Claude Code 和 Codex 的 agent 停下来时，讣告把它这次新建、还没归类的文件列给它，请它把调试脚本、日志、截图登记寿命或下葬，正式成果留下。每个会话最多一次，没有就不打扰；其他 agent 改在下一次会话开始时提。`[hooks] session_cleanup = false` 关掉。
- **下葬前再问一次 Git**：按规则或提议登记的东西，到期时如果已经被提交，就不下葬。
- **提议会自己过期**：已经被提交或删掉的条目从提议里去掉，全部失效的提议自动撤回（记进审计日志，不算你拒绝）。

## 规则

```powershell
obit rules                       # 当前项目生效的规则（内置规则 + 已信任的 .obitrules）
obit rules check debug.log out/  # 预览：会登记什么、按哪条规则（不做任何改动）
obit rules apply debug.log       # 按规则登记
```

内置规则覆盖 agent 常见的垃圾：`.playwright-mcp/`、`test-results/`、`__pycache__/`、`*.log` 等。项目根目录的 `.obitrules` 用 `.gitignore` 的写法，每条后面跟寿命：

```
output/**        7d      # output 下的每一项单独计算寿命
!output/keep/**          # 永远不碰（否定规则优先，连上级目录都不会被整体登记）
test-results/    off     # 关掉某条内置规则
```

和 `.gitignore` 不同的地方：否定规则优先，不是最后一条为准；Windows 上匹配不分大小写；写错的模式（比如没闭合的 `[`）会报错并指出文件和行号，这个项目的自动登记先停下。

时长单位：`s` `m` `h` `d` `w`，可以组合（`1d12h`）。

## 自动登记的硬规则

- 只登记 Git 工作区里、没有被 Git 跟踪的东西。
- 目录里只要有一个被跟踪的文件，整个目录都不碰。
- Git 回答不了时一律跳过。
- 已经有寿命的不会被改短。
- 拒绝过的项目在任何模式下都不会被直接登记；文件夹策略和 `.obitrules` 的信任始终要你点头。

## 项目规则要先信任

仓库自带的 `.obitrules` 在你审过并执行 `obit trust` 之前不生效，防止别人的仓库用规则收走你的私人文件。信任时记下文件的 SHA-256，内容一改就要重新审。非交互环境必须加 `--yes`；CI 里可以用 `OBIT_TRUST_PROJECT_RULES=1`。

## 会自己下葬的临时目录

```powershell
$dir = obit mktemp 1d            # 项目里放在 .obit/tmp/（不进 Git），否则放在系统临时目录
```

bash 里写 `dir=$(obit mktemp 1d)`。
