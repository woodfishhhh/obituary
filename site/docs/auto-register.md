# 什么进讣告

## agent 和你决定，讣告按时下葬

什么进讣告，由 agent 和你自己决定（默认，`[proposals] mode = "off"`）：

- **agent 自己登记**：它写调试脚本、日志、截图时用 `obit mark <路径> 2d` 给它寿命，要临时目录用 `obit mktemp 1d`，拿不准的东西 `obit bury`。`obit init` 写给 agent 的说明里讲了这些。
- **你右键放进来**：Windows 上在资源管理器里右键文件或文件夹（可以多选）→「放进讣告」→ 1 天、7 天、30 天，或「现在埋掉（可恢复）」。见 [小窗口、托盘和右键菜单](./desktop)。
- **文件夹策略**：给下载这类文件夹设一个寿命，见 [文件夹策略](./folder-policies)。

进来的东西到期自动下葬，墓地里 7 天内都能原样复活。除此之外什么都不会自己进讣告。

- **收工整理**：Claude Code 和 Codex 的 agent 停下来时，讣告把它这次新建、还没归类的文件列给它，请它把调试脚本、日志、截图登记寿命或下葬，正式成果留下。每个会话最多一次，没有就不打扰；其他 agent 改在下一次会话开始时提。`[hooks] session_cleanup = false` 关掉。
- **从旧版本升级**：讣告把这个设置切到关闭一次（之后你再改的设置一直有效），以前自动登记的依赖、构建产物和缓存一并撤回：东西留在原处，不再计时。

## 需要时打开自动登记

在小窗口「设置」或「待你决定」页切换，或在 `config.toml` 里设 `[proposals] mode`：

- `"tiered"`（分级）：agent 这次会话自己新建的文件（hook 看着它写的，会话开始时没有它，文件系统记的创建时间也在会话开始之后），和会话里为这个项目起的 Docker 容器（见 [Docker 容器](./docker)），直接进讣告，事后告诉 agent，也列在 `obit proposals` 和「待你决定」的「已自动处理」里。其余的列成提议：会话开始前就在的文件，或者 hook 没看到 agent 写的文件。你同意后执行 `obit approve <id>`，此后这个项目里规则认得的东西都直接登记；`obit reject <id>` 则表示以后别再自动登记这个项目。
- `"auto"`（全自动）：自动登记找到的东西都直接进，事后告诉你。
- `"ask"`（全部都问）：都先列成提议。

```powershell
obit proposals           # 等你点头的提议，和没问你就登记了的东西
obit approve 3           # 同意：登记里面列的东西
obit reject 3            # 拒绝
obit spare 12            # 撤回一项自动登记：东西留在原处，不再计时
obit extend 12 1w        # 留久一点
```

- **依赖、构建产物和缓存**（`node_modules`、`dist`、`.turbo`、`__pycache__` 等）在任何模式下都不自动登记，也不进提议；要清理就自己 `obit mark`。
- **超大的东西**（超过 1 GB 或 200 个文件）不是 agent 新建的，照样先提议。
- **会话差分**：会话开始时记一份快照（存在数据目录，不往你的仓库里放东西），结束时对比。规则认得的东西按模式处理；规则认不得的新文件既不登记也不提议。
- **切换之后**，还在等你的提议由后台按新模式重新分一次。
- **下葬前再问一次 Git**：按规则或提议登记的东西，到期时如果已经被提交，就不下葬。
- **提议会自己过期**：已经被提交或删掉的条目从提议里去掉，全部失效的提议自动撤回（记进审计日志，不算你拒绝）。

## 规则

```powershell
obit rules                       # 当前项目生效的规则（内置规则 + 已信任的 .obitrules）
obit rules check debug.log out/  # 预览：会登记什么、按哪条规则（不做任何改动）
obit rules apply debug.log       # 按规则登记
```

`obit rules apply` 随时可以手动按规则登记；打开自动登记后，hook 也按这些规则登记。内置规则覆盖 agent 常见的垃圾：`.playwright-mcp/`、`test-results/`、`*.log` 等，编辑时留下的备份（`*.bak`、`*.bak.*`、`*.orig`、`*.rej`、`*.old`、`*.backup`、`*~`）留 7 天；LevelDB 的 `LOG.old` 不算。项目根目录的 `.obitrules` 用 `.gitignore` 的写法，每条后面跟寿命：

```
output/**        7d      # output 下的每一项单独计算寿命
!output/keep/**          # 永远不碰（否定规则优先，连上级目录都不会被整体登记）
test-results/    off     # 关掉某条内置规则
```

和 `.gitignore` 不同的地方：否定规则优先，不是最后一条为准；Windows 上匹配不分大小写；写错的模式（比如没闭合的 `[`）会报错并指出文件和行号，这个项目的自动登记先停下。

时长单位：`s` `m` `h` `d` `w`，可以组合（`1d12h`）。

## 自动登记的硬规则

- 只登记 Git 工作区里、没有被 Git 跟踪的东西。
- 目录里只要有一个被跟踪的文件，整个目录都不碰。
- Git 回答不了时一律跳过。
- 已经有寿命的不会被改短。
- 拒绝过的项目在任何模式下都不会被直接登记；文件夹策略和 `.obitrules` 的信任始终要你点头。

## 项目规则要先信任

仓库自带的 `.obitrules` 在你审过并执行 `obit trust` 之前不生效，防止别人的仓库用规则收走你的私人文件。信任时记下文件的 SHA-256，内容一改就要重新审。非交互环境必须加 `--yes`；CI 里可以用 `OBIT_TRUST_PROJECT_RULES=1`。

## 会自己下葬的临时目录

```powershell
$dir = obit mktemp 1d            # 项目里放在 .obit/tmp/（不进 Git），否则放在系统临时目录
```

bash 里写 `dir=$(obit mktemp 1d)`。
