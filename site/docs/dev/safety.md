# 安全模型

路径告诉讣告去哪里找，文件身份才说明找到的是不是同一个对象。到期前文件可能被改名，也可能已经被另一个同名文件替换。不能只凭路径埋掉后来者。

改动移动、下葬或删除文件的代码时，先写一个失败测试，验证不该删除的文件仍然存在，再修代码。修完后临时换回能编译的错误实现，确认测试确实失败，再恢复修复。

| 阶段 | 必须守住的条件 |
| --- | --- |
| 登记与定位 | `Guard` 检查受保护路径；自动来源还须检查 Git 状态。不能确认时，不把路径当作可自动处理的对象。 |
| 下葬 | `FS.MovePinned` 复核身份再移动；平台无法满足相应安全条件时应保留原件，不能改用删除。 |
| 复活 | 先验证坟墓归属、清单和恢复父目录，再用 `MovePinnedInto` 恢复。原名被占用时另取名字，不覆盖。 |
| 火化 | 只有显式或到期的 `Purge` 流程可以永久移除已验证坟墓里的用户内容。回收站失败不是火化许可。 |

`ErrNotFound` 表示已确认不存在，`ErrUnsafe` 表示拒绝。权限错误、共享冲突等暂时性失败不是「文件消失」；保留记录以便重试。审计写入失败不能撤掉已完成操作的状态。具体平台的保证和限制见[文件系统契约](https://github.com/woodfishhhh/obituary/blob/main/docs/architecture.md)。
