# 架构

以「给文件设定寿命」为例：CLI 解析路径和时间，应用层打开服务，核心记录文件身份和到期时间。命令成功并不意味着文件已经移动；移动发生在到期处理或显式下葬时。

## 谁作决定

| 入口或模块 | 职责 |
| --- | --- |
| CLI、小窗口、MCP | 把输入转换成服务调用，把结果转换成退出码、界面状态或协议回复。入口不自行移动文件。 |
| 宿主 hook | 把宿主事件转换成 `internal/hook.Event`；慢操作交给 runner，不阻塞工具调用。 |
| `internal/integrate` | 计算安装计划，再应用到宿主配置。应用时复核原文，避免覆盖用户刚做的编辑。 |
| `internal/app`、`obitd` | 组装平台服务，按调度或事件唤醒后台处理；到期项仍由核心判定。 |
| `internal/core/lifecycle`、`internal/core/ledger`、`internal/core/guard`、`internal/core/fs` | 复核保护规则和身份，协调文件移动、账本修订、恢复与审计。 |

## 到期之后

一次 sweep 认领到期条目，重新定位文件并核对身份。下葬时先独占创建坟墓、写清单，再移动内容；移动与账本更新中间若中断，恢复流程用清单和实际位置判断结果。账本写回时检查修订号，不能用旧快照盖掉用户刚做的延期。

账本描述当前状态，审计日志描述已发生的操作。审计暂时写不进去时，由待发队列补记；不要为了补日志再移动一次文件。具体错误如何处理见[安全模型](./safety)。
