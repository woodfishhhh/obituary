# 接入新 agent

先确定宿主实际提供什么。写入后的 hook 能报告已经发生的写入；工具调用前的 hook 才有机会拒绝删除。MCP 是由模型主动调用的工具，Skill 是指导文字；两者都不能替代一个宿主没有提供的事件。覆盖表不要把它们合并成一个「支持」。

1. 在 `internal/hook` 增加薄适配器，把真实 payload 转成公共 `Event`。用脱敏夹具测试缺失字段、路径和事件种类；耗时工作交给 runner。
2. 在 `internal/integrate` 描述安装目标，经 `internal/userdirs` 定位配置。检查已有配置、重复安装与卸载：只移除讣告拥有的内容。新的安装步骤也需要 `doctor` 诊断。
3. 单独核对 MCP、Skill 和宿主插件的发现方式。不能替用户作出的决定，如信任项目规则，不应变成 MCP 工具。
4. 核对 `docs/agents.md` 的生成结果，再更新 `site/docs/.vitepress/agents` 和首页数据对应的指南。用真实宿主验证一次安装和一次触发；写入成功与 hook 收到事件是两个不同的观察点。
