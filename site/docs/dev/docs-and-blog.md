# 文档与博客规范

手册回答「现在怎样做」，架构文档回答「哪些条件必须成立」。把一个命令放进示例之前，在一次性目录用实际版本执行，核对退出码和可观察结果。手工测试同时隔离 `OBIT_HOME` 与 `OBIT_CONFIG_DIR`；不要借用日常账本、注册表配置或回收站来做演示。

开发博客可以写「为什么改」。时间线以实际开发日期为准，事实链接到公开提交、issue、PR、变更日志或相应版本的代码路径。构建成功不代表通过原生桌面验收；推测、设计意图和已经验证的行为要分开。

公开稿不署名，不引用内部记录，不含本机账号、私有路径、地址、凭据或聊天原文。开发文档须有中英文对应页；提交前分别查看普通版和国内镜像版的代码块、链接和语言切换。
